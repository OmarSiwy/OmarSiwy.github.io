## The reader and the method

The reader is an ECE student who wants to *remember* this material. Four rules
come from that:

1. **Breadth first, then depth.** The note opens with the whole chapter at its
   lowest resolution: one diagram plus the 3–6 results to remember. Each later
   section goes one level deeper than the one before (black box, then
   first-order model, then second-order effects, then short-channel/physics/
   simulation). A reader who stops after any section still has a correct,
   coarser picture.
2. **Diagram, then math, then words.** Write it like slides. A section is
   usually: a diagram, the boxed result, and one or two lines saying what it
   means. Text explains only what the picture and equation can't. No textbook
   throat-clearing, no restating the heading.
3. **Memorize what's outside the folds.** Everything a reader must remember
   stays in the open. Derivations, physical background, edge cases, and
   "nice to know" details go in **collapsed** callouts:

   ```md
   > [!note]- Derivation: square law from charge × velocity
   > ...
   ```

   The `-` makes it fold closed by default. Title each one so the reader knows
   what's inside without opening it (`Derivation: …`, `Detail: …`, `Why: …`).
   A standalone diagram that carries the idea is never folded. A diagram that
   only helps a derivation goes inside the fold with it.
4. **Remarks connect the pieces.** When an idea depends on earlier material,
   remind the reader right there, in an open callout:

   ```md
   > [!tip] Remark
   > This is the $r_o$ from [[MosFETs#Channel-Length Modulation]]: $r_o = 1/(\lambda I_D)$.
   ```

   One or two lines: what to recall, and the link. Use them wherever the
   textbook says "recall that" or silently assumes something from an earlier
   chapter, and wherever two results in this note are secretly the same idea.

Use `> [!important]` sparingly, for the one or two facts the whole chapter
hangs on. Box key results with `\boxed{}`.

## Spec translation (required for every non-amplifier block)

The owner designs with gm/ID, which sizes *amplifiers*. So every note about a
block that is not itself an amplifier (references, bias generators, mirrors,
SC circuits, samplers, comparators, oscillators, PLLs, DACs, ADCs, filters,
SerDes TX/RX/CDR, RF blocks, ...) needs a `## Spec translation` section,
placed right after the big picture (before the deep levels):

1. The block's own specs, from the source (e.g. a bandgap: TC in ppm/°C,
   PSRR, noise, start-up, line regulation; an ADC stage: residue gain error,
   settling to ½ LSB, kT/C).
2. A table mapping each block spec to the amplifier(s)/devices inside it and
   the **amplifier specs** that set it: DC gain, GBW / unity-gain frequency,
   phase margin, slew rate, settling time, input-referred noise, offset,
   output swing, input CM range, output impedance, CMRR/PSRR, power. Use the
   spec names and definitions in [[Single-Stage#Amplifier Specifications]].
3. The derivation of each mapping (e.g. settling to ½ LSB in time T →
   A₀ ≥ 2^(N+1)/β and ω_u ≥ (N+1)·ln2/(βT)) in a folded callout; the
   resulting inequality boxed in the open.
4. Where each amplifier spec lands in sizing: which ones fix g_m/I_D, I_D, L,
   f_T, g_m r_o, as a short table, with a Remark linking to
   [[gm-ID Design Methodology]] for the method itself (don't re-teach it).
5. A worked numeric example from a source when one exists (block spec →
   amplifier spec → gm/ID, L, I_D).

System-level notes (e.g. Channels, Signaling and BER) don't need the full
table; instead end with "what this implies for the circuit blocks" and link to
the block notes that own the translation.

## Diagrams

Draw them yourself in TikZ/CircuitikZ; that's the default visual. Exact block
format (works in both Obsidian TikZJax and the site build):

````
```tikz title="Short caption"
\usepackage{circuitikz}
\begin{document}
\begin{circuitikz}
  ...
\end{circuitikz}
\end{document}
```
````

- Fence is `tikz`. Environment is `circuitikz` (superset of tikzpicture; use it
  even for plots and block diagrams). No `\documentclass`.
- `\usetikzlibrary{...}` goes after `\usepackage`. No `arrows.meta`: use
  `>=latex` / `stealth`. Avoid `pgfplots`; draw plots with `\draw plot` or
  `\draw[domain=...] plot (\x,{...})`. pgfmath overflows above 16384.
- Kinds that carry the most: schematics (`nmos`, `pmos`, `R`, `C`, `I`,
  `vsource`, `ground`), small-signal models, I–V / Bode / transfer curves with
  labelled regions, block diagrams of loops and systems, cross-sections.
- Label everything a reader would ask about. Caption from the book figure it is
  based on, e.g. *after Razavi Fig. 2.9*.

Compile and look at every diagram before you finish. Other agents are writing
other chapters in parallel, so check diagrams one at a time with the preview
script, in your own `/tmp/<your-slug>/` directory. Put exactly the fence's
contents in a file whose name contains `circuitikz`, then, from the repo root:

## Layout notes: visuals carry the note

Layout is spatial; a layout note that is mostly prose has failed. For any
note under `Layout/`, or any layout section in another note:

- Every layout concept gets a drawn top view, and a cross-section where depth
  matters (wells, junctions, guard rings, latch-up paths, ESD current paths).
  Draw layers as filled rectangles using EXACTLY the series legend defined in
  the first diagram of `Layout/CMOS Processing.md` (copy its TikZ colour
  definitions): n+ diffusion green, p+ diffusion orange, poly red, M1 blue,
  M2 purple, contacts/vias black, n-well light cyan dashed, STI grey, p-sub
  peach. Put a compact legend in each note's first layout diagram.
- Show patterns as tiles with device labels (ABBA, ABAB, common-centroid
  arrays, interdigitated fingers, dummies), and draw **good vs bad side by
  side** with the failure annotated (gradient arrow, current crowding, etc.).
- Gradients and mismatch: draw the gradient over the array and show
  numerically why the pattern cancels it.
- Aim for roughly one diagram per `###`. Text is labels, captions and the
  rule; the rule list itself goes in the open, its justification in folds.
- Crop a figure from Hastings only for photos/micrographs; redraw everything
  else.

## Output

One file at the assigned path. Frontmatter:

```md
---
title: <Title>
description: <one concrete line>
kind: topic
status: growing
aliases:
  - <Title>
---
```

Then:

1. **The big picture**: the chapter on one screen. A diagram, the must-remember
   results, and a one-line map of the sections below.
2. **Sections, coarse to fine.** `##` per level of depth, `###` per idea.
3. **Design intuition / trade-offs**: a table of the knobs (what you change,
   what improves, what it costs). This is what a designer actually recalls.
4. **`## Cheat sheet`**: every boxed equation in the note, in one table, no
   derivations.
5. **`## References`**: sections and pages actually used, per source.

No length target. Length comes from depth in the folds, not from prose in the
open. If the open (unfolded) text reads like a textbook paragraph, cut it.

If the target file already has content written by the owner, keep their
structure, voice and images (`![[Pasted image ...]]`) where they fit; fix any
errors in it and say what you fixed.
