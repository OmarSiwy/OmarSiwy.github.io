**Specification.** Input: a $k$-bit vector $x$ sampled on the rising edge of one clock, plus a synchronous reset. State: $N$ symbols held in $s$ flip-flops. Output: an $m$-bit vector $z$ that is a function of the state (Moore) or of the state and the current input (Mealy). Accuracy: sequential logic is **exact** — there is no ulp to spend, so the only "error" available is *latency*, measured in whole cycles, and Moore vs. Mealy is a one-cycle argument. Optimized here: $f_{\max}$ first (the register-to-register path through the next-state logic), then flop and LUT count.

Every cycle-time claim below rests on the register constraint derived in [[Introduction to Flip-Flops & Latches]]:

$$T_c \;\ge\; t_{pcq} + t_{pd}^{\text{NSL}} + t_{\text{setup}} + t_{\text{skew}}$$

and the hold inequality $t_{ccq} + t_{cd} \ge t_{\text{hold}} + t_{\text{skew}}$. Nothing in this note re-derives them; every design move below is an attempt to shrink $t_{pd}^{\text{NSL}}$ or to stop caring about it.

## The synchronous discipline

The discipline is one rule: **every cycle in the signal-flow graph passes through at least one edge-triggered flip-flop, and every flop takes the same clock.** Combinational logic is then acyclic by construction.

What that buys is the reason digital design scales at all:

- **Time becomes discrete.** The circuit is only ever *observed* at clock edges. Between edges the combinational cloud may glitch arbitrarily — multiple transitions per node, hazards from unequal path delays, no defined value at all — and none of it is sampled. The correctness argument reduces to "did every node settle before $t_{\text{setup}}$", one inequality per path, instead of a race analysis over continuous time.
- **Composition is closed.** Two synchronous blocks wired together are synchronous. This is false for the asynchronous style of [[Asynchronous Sequential Logic]], where a feedback loop with no flop in it makes the *delays themselves* part of the state, and composition can introduce oscillation that neither block had alone.
- **Verification becomes finite.** State is exactly the flop contents, $2^s$ values, so model checking and equivalence checking are decidable searches rather than differential-equation problems.

The price is $t_{\text{setup}}$ and the clock tree: the slowest path in the whole design sets $T_c$ for every path, so a machine is as fast as its worst combinational cloud, and the clock must reach several million flops within $t_{\text{skew}}$.

> [!important] Glitches are free inside a cycle and fatal across one
> This is the single fact the rest of the note hangs on. Combinational output logic may glitch as much as it likes because a downstream flop samples only at the edge. The moment an output leaves the synchronous island — an asynchronous RAM write-enable, an off-chip strobe, a clock-gating cell, an input to a *different* clock domain — glitches become real events. That is the whole practical case against Mealy outputs, and the reason "register the output" is the default advice.

Formally the machine is the 6-tuple $(X, Q, Z, \delta, \lambda, q_0)$ with

$$
q^{n+1} = \delta(q^n, x^n), \qquad
z^n = \begin{cases}\lambda(q^n) & \text{Moore}\\ \lambda(q^n, x^n) & \text{Mealy}\end{cases}
$$

$\delta$ and $\lambda$ are pure combinational logic — everything from [[Combinational Logic]] applies to them unchanged. The *only* sequential element in the entire structure is the state register. This is worth saying plainly because it is what makes FSM design a Boolean-algebra exercise: pick an encoding, and $\delta$ and $\lambda$ become $s+m$ Boolean functions of $s+k$ variables, minimized by the laws in [[Boolean Algebra]].

The critical path is the loop $q \to \delta \to d \to q$. Note that $\lambda$ is *not* in it — output logic depth costs you nothing in $f_{\max}$ unless the output feeds another machine's $\delta$.

## Moore

$z = \lambda(q)$. The output depends on the state alone, so it is stable for a full cycle and changes only just after a clock edge.

Consequences, all of them following from that one equation:

- **The output is a registered signal in all but name.** It is a combinational function of flop outputs only, so it inherits their timing: one $t_{pcq}$ plus $\lambda$'s depth after the edge, then flat. Glitch exposure is limited to the $\lambda$ transition window and vanishes entirely if $\lambda$ is a wire (i.e. if the output *is* a state bit).
- **It costs a cycle.** The information "the last input bit completed the pattern" must be latched into the state before it can be observed, so the response appears one cycle after the input that caused it.
- **It costs states.** Two situations that behave identically going forward but should emit different outputs *cannot be merged*, because the output is carried by the state. The 1011 detector below has exactly this: states $S_1$ and $S_4$ have identical next-state behaviour and differ only in output. That extra state is literally the output register, paid for in the state space.
- **It composes safely.** Feeding a Moore output into a write-enable, an asynchronous FIFO, or another clock domain is safe by construction.

## Mealy

$z = \lambda(q, x)$. The output reacts within the same cycle as the input.

- **One cycle earlier.** The response is combinational from $x$, so it is visible in the cycle of the triggering input rather than the next one.
- **Fewer states, often strictly fewer.** States that differ only in "what output did I just emit" collapse, because the emission is attached to the *edge*, not the node. For the 1011 detector: 4 states instead of 5.
- **A new combinational path appears: $x \to \lambda \to z$.** This does not lengthen $q\to\delta\to q$, so it does not hurt $f_{\max}$ *locally*. It hurts at the boundary: the arrival time of $z$ is now $t_{\text{arrival}}(x) + t_{pd}^{\lambda}$, and if $x$ itself is a Mealy output of the upstream block, these paths chain. Two cascaded Mealy machines have a combinational path spanning both, and a ring of them has a combinational cycle — which breaks the synchronous discipline outright.
- **The output glitches.** $z$ tracks $x$ combinationally, so any glitch or late transition on $x$ propagates to $z$ mid-cycle. Sampling $z$ with a flop is fine; using it as an enable, strobe, or clock is not.

> [!note] They are equally expressive
> Every Mealy machine has an equivalent Moore machine (split each state by incoming output label — at most $|Q|\cdot|Z|$ states) and vice versa (a Moore machine is the Mealy machine whose $\lambda$ ignores $x$). The choice is never about *what* can be computed, only about *when* the answer appears and what it costs.

The **state table** is the same information as a truth table with the state as an extra input column — which is the point: once encoded, it *is* a truth table, and $\delta$ falls out of it by the usual minimization.

Two properties to check on the graph before encoding anything:

- **Completeness.** Every state must have an outgoing edge for every input combination, $2^k$ of them. A missing edge in HDL becomes an inferred latch, which silently leaves the synchronous discipline.
- **Determinism.** No two outgoing edges of a state may have overlapping input conditions. A `casez` with overlapping patterns and `parallel_case` asserted will synthesize to something the simulator does not model.

## State assignment

Choosing the code $\text{enc}: Q \to \{0,1\}^s$ fixes $\delta$ and $\lambda$ as Boolean functions. Different codes give wildly different logic for the same machine; the assignment problem is NP-hard, and the three defaults are:

**Binary**, $s = \lceil \log_2 N\rceil$. Minimum flops. Every next-state bit is a function of *all* $s$ state bits plus the inputs, so fan-in is $\lceil\log_2 N\rceil + k$ and each output bit needs its own minimization. Cheapest register, most expensive and least regular $\delta$.

**Gray**, $s = \lceil\log_2 N\rceil$. Same width, adjacent states differ in one bit. Only worth the effort when the STG is largely a chain or a counter, where it makes most transitions flip a single flop — that halves switching energy on the state register and, more importantly, makes the state bus safe to sample from another clock domain (only one bit can be metastable at a time). For an arbitrarily connected STG, Gray is just an arbitrary binary code.

**One-hot**, $s = N$, exactly one bit set. The next-state equation for state $S$ is a direct transcription of $S$'s *incoming* edges:

$$q_S^{+} \;=\; \bigvee_{(T,\,c)\;\to\;S} q_T \cdot c$$

where $c$ is the input condition on the edge. Fan-in is the in-degree of $S$ plus the width of the conditions — **independent of the total state count $N$**. That is the whole argument: as the machine grows, binary's fan-in grows as $\log_2 N$ while one-hot's does not grow at all.

The counterpart is the invariant $\sum_S q_S = 1$, which must be *established* (reset to $q_{S_0}=1$) and can be *lost* (see the recovery section). Output logic also becomes trivial: a Moore output is an OR of the state bits that assert it, and often a single bit with no logic at all.

## State minimization

Two states are **equivalent** if no input sequence distinguishes them at the output. Merging equivalent states shrinks $N$, which shrinks $s$ for binary encodings and flop count for one-hot. The Moore–Hopcroft procedure is partition refinement, and it terminates because each round either splits a block or is a fixed point:

1. $P_0$ = partition by output.
2. $P_{i+1}$ = refine $P_i$: two states stay together only if, for **every** input, their successors land in the same block of $P_i$.
3. Stop when $P_{i+1} = P_i$. Blocks are the equivalence classes.

Run on the 5-state Moore detector defined below:

| Round | Partition | Split because |
| --- | --- | --- |
| $P_0$ | $\{S_0,S_1,S_2,S_3\}\;\vert\;\{S_4\}$ | $S_4$ is the only state with $z=1$ |
| $P_1$ | $\{S_0,S_1,S_2\}\;\vert\;\{S_3\}\;\vert\;\{S_4\}$ | $S_3$ alone reaches $\{S_4\}$ on $x=1$ |
| $P_2$ | $\{S_0,S_1\}\;\vert\;\{S_2\}\;\vert\;\{S_3\}\;\vert\;\{S_4\}$ | $S_2$ alone reaches $\{S_3\}$ on $x=1$ |
| $P_3$ | all singletons | $S_0\xrightarrow{0}S_0$ but $S_1\xrightarrow{0}S_2$, now different blocks |

Five classes, so the machine is already minimal. Note what $P_0$ did: it separated $S_4$ from $S_1$ *purely on output*, even though their successor behaviour is identical ($0\to S_2$, $1\to S_1$ for both). Delete the output column — as Mealy does, by moving the output onto the edges — and those two states merge immediately. That merge, and no other, is the entire 5-vs-4 state difference between [[Synchronous Sequential Logic#Moore|Moore]] and [[Synchronous Sequential Logic#Mealy|Mealy]] here.

> [!note] Minimal is not always smallest
> Minimizing $N$ minimizes the *state count*, not the gate count. A machine with $N=9$ needs 4 flops; merging to $N=8$ saves a flop, merging 9 to 5 saves nothing in width. And under one-hot with modern synthesis, merging states that had cheap incoming edges can *increase* $\delta$ by concentrating fan-in. Minimize to reduce flops or to expose don't-cares, not reflexively.

## Unreachable and unused states

With $s$ flops there are $2^s$ codes and only $N$ states. The leftovers split into two kinds:

- **Unused codes** — $2^s - N$ of them for binary ($0$ when $N$ is a power of two, up to $N-1$ otherwise), and $2^N - N$ for one-hot, which is nearly the entire code space. Synthesis treats them as don't-cares and uses them to simplify $\delta$, which is exactly why an unused code, once entered, can transition anywhere at all — including into a closed loop containing none of the real states.
- **Unreachable states** — legal codes with no incoming edge from the reset state. Dead logic; synthesis prunes them.

The machine can only enter an unused code through something outside the model: a single-event upset, a reset that is asynchronous on one flop and not another, a state bus crossing a clock domain without a synchronizer, or setup violation on part of the register.

**Safe FSM recovery**, cheapest first:

1. **Reset covers every state flop.** A machine that reaches its start state on reset cannot be stuck permanently, only until the next reset. This is free and is the baseline.
2. **A `default` arm that returns to reset state.** In HDL this is one line. It is also the line synthesis deletes, because it is unreachable in the model — you must mark the state register as safe (`fsm_safe_state` / `SAFE_IMPLEMENTATION` style attributes) or the tool will optimize the recovery logic away and the RTL simulation will lie to you.
3. **Explicit decoded check.** For one-hot, $\text{legal} = \big(\bigvee_S q_S\big) \wedge \neg\!\!\bigvee_{S\ne T} (q_S q_T)$ — at least one hot, no two hot. Force the reset state when it fails. Cost is $O(N^2)$ pairwise terms, usually built as a population-count comparison instead.
4. **Distance-3 encoding.** Choose codes with minimum Hamming distance 3 so any single bit flip is detectable and correctable. Costs extra flops and forfeits the encoder's freedom to simplify $\delta$; reserve it for radiation or safety-critical parts.

## Datapath plus control

Anything larger than a handful of states stops being one FSM. The standard decomposition (FSMD) splits the design into:

- a **datapath** — registers, adders, multipliers, muxes, memories, sized by the arithmetic in [[Number Formats]] and built from the operators in this vault — carrying wide data, with no branching of its own;
- a **control FSM** — narrow, holding only the *schedule*, driving a control word (mux selects, register enables, operator modes) and reading back a few status bits (zero flags, comparator results, handshake ready/valid).

The split is what keeps state counts sane: an 8-bit accumulator as datapath is one register; as FSM state it would be 256 states. State belongs in the control FSM only when the *logic branches* on it.

The path that matters is the loop **status flag $\to$ next-state logic $\to$ control word $\to$ datapath $\to$ status flag**. This is the one loop pipelining cannot break, and it is why a comparator output feeding a control decision often ends up the critical path of a design whose datapath is far deeper. Two standard mitigations: register the control word (a Moore control FSM, costing one cycle of control latency, usually absorbed by the schedule), and speculate the branch by computing both control words and selecting late.

## Pipelining and retiming

Both move registers to shorten $t_{pd}$ between them; they differ in whether the cycle count changes.

**Pipelining** cuts a *feed-forward* combinational path with new registers. $p$ stages ideally give $T_c \to T_c/p$, latency $\to p$ cycles, throughput one result per cycle. It applies to datapaths without reservation and to FSM output logic $\lambda$ (registering $z$ turns a Mealy output into a Moore output one cycle late), and **not** to $\delta$, because $\delta$ sits in a feedback loop: inserting a register there does not pipeline the machine, it builds a *different* machine.

**Retiming** (Leiserson–Saxe) moves existing registers across combinational nodes without changing I/O behaviour. Move a register backward across a gate and it must be replicated onto every input; forward, onto every output. The invariant is what makes it safe and what limits it: **register count around any directed cycle is conserved.** Hence the iteration bound

$$T_c \;\ge\; \max_{\text{loops } \ell} \frac{\sum_{v\in\ell} t_{pd}(v)}{\#\text{registers in }\ell}$$

For a plain FSM every loop through $\delta$ contains exactly one register, so the bound is the full delay of $\delta$ — **no amount of retiming makes an FSM faster than its next-state logic.** That is the hard floor, and the only ways under it are algorithmic:

- **Restructure $\delta$**: re-encode (one-hot, to cut fan-in), factor the machine into communicating smaller machines, or precompute transition conditions one cycle early into a flop.
- **C-slow retiming**: replace each register with $C$ in series and interleave $C$ independent problem instances. The loop now has $C$ registers, so the bound drops by $C\times$ — at $C\times$ the latency per instance, and only if you actually have $C$ independent streams (packets, channels, threads).

## FPGA mapping

An FPGA slice pairs each LUT with a flip-flop that is otherwise wasted, which changes the encoding arithmetic completely.

- **Flops are free until they aren't.** If the design's LUT count already forces $N$ slices, one-hot's $N$ flops cost zero extra area. The binary encoding's saving of $N - \lceil\log_2 N\rceil$ flops buys nothing, because those flops were unused silicon.
- **Depth is quantized to LUT levels.** A $\lambda$- or $\delta$-bit with $\le 6$ inputs is one LUT6, roughly $0.1$–$0.3$ ns plus routing; 7 inputs is two levels plus a route between them, which more than doubles the delay because routing dominates. So the metric is not literal fan-in, it is $\lceil$fan-in$/6\rceil$ levels.
- **This is where one-hot wins.** Binary next-state fan-in is $\lceil\log_2 N\rceil + k$, crossing 6 inputs at about $N > 16$ for $k=2$. One-hot fan-in is (in-degree $+\ k$), typically 3–5 regardless of $N$ — a 64-state one-hot machine still maps to one LUT level per state bit, while binary needs two or three. Vivado and Quartus both default to one-hot for exactly this reason, and re-encode automatically above a small state count.
- **Corollaries.** One-hot output decoding is free (`z = q_S`, a wire). Very small machines ($N \le 4$, as below) fit inside one LUT level either way, so binary is not worse — use whatever reads better. And a state register targeted for safe recovery must carry a `KEEP`/`fsm_safe_state` attribute or the unused-code don't-cares get absorbed into the LUT equations.

## Trade-offs

Moore vs. Mealy, general behaviour:

| | Moore | Mealy |
| --- | --- | --- |
| Output latency | 1 cycle after the triggering input | same cycle |
| Path $q\to\delta\to q$ (sets $f_{\max}$) | identical | identical |
| Extra path $x\to\lambda\to z$ | none | yes — chains through cascaded machines |
| States (1011 detector) | 5 | 4 |
| Output glitches | only during $\lambda$'s transition after the edge; none if $\lambda$ is a wire | tracks every glitch on $x$ |
| Safe as enable / strobe / cross-domain | yes | no, register it first |

Encoding, counted from the worked example below (Mealy, $N=4$, $k=1$, mapped to LUT6 + FF):

| | Binary | One-hot |
| --- | --- | --- |
| Flip-flops | 2 | 4 |
| $\delta$ equations | $s_0^{+}=x$ (free), $s_1^{+}$ 3-input | 4 equations, $\le 4$ inputs each |
| LUT6 for $\delta+\lambda$ | 2 | 5 |
| LUT levels in the critical loop | 1 | 1 |
| Fan-in growth with $N$ | $\lceil\log_2 N\rceil + k$ | in-degree $+\,k$, flat in $N$ |
| Crossover ($k=2$, LUT6) | wins below $N\approx16$ | wins above |

Pick **Moore** by default — it is the safe composition and the registered output. Pick **Mealy** when the one cycle is genuinely on a critical loop (handshake ready/valid, a status flag feeding a control decision) and the consumer is a flop, not an enable. Pick **binary** for ASIC and for small FPGA machines; pick **one-hot** on FPGA above roughly 16 states, or whenever $\delta$ is spilling to a second LUT level. Pick **Gray** only for chain-shaped machines or a state bus that crosses clock domains.

## Worked example: overlapping 1011 detector

$z=1$ whenever the last four input bits were $1011$, overlaps included, so $1011011$ must fire twice.

### Mealy version

Four states, named for the longest prefix of $1011$ that is a suffix of the input so far: $A=\varepsilon$, $B=1$, $C=10$, $D=101$.

| Present | $x=0$: next / $z$ | $x=1$: next / $z$ | Reasoning for the $x$-branch |
| --- | --- | --- | --- |
| $A$ | $A$ / 0 | $B$ / 0 | a $1$ starts a match |
| $B$ | $C$ / 0 | $B$ / 0 | $11$: keep the last $1$ |
| $C$ | $A$ / 0 | $D$ / 0 | $100$ throws everything away |
| $D$ | $C$ / 0 | $B$ / **1** | match; the trailing $1$ is a fresh prefix |

The $D \xrightarrow{1} B$ edge is the overlap: after firing, the machine keeps the final $1$ rather than restarting at $A$.

**One-hot equations.** Transcribe *incoming* edges, $q_S^{+}=\bigvee q_T c$:

$$
\begin{aligned}
q_A^{+} &= q_A\bar{x} + q_C\bar{x} &&= (q_A+q_C)\,\bar{x} &&\text{distributivity of AND over OR}\\
q_B^{+} &= q_Ax + q_Bx + q_Dx &&= (q_A+q_B+q_D)\,x &&\text{same}\\
q_C^{+} &= q_B\bar{x} + q_D\bar{x} &&= (q_B+q_D)\,\bar{x} &&\text{same}\\
q_D^{+} &= q_Cx &&&&\text{single incoming edge}\\
z &= q_Dx &&&&\text{the one edge labelled }1/1
\end{aligned}
$$

**Check the one-hot invariant is preserved.** Sum the four next-state functions:

$$
\begin{aligned}
\textstyle\sum q^{+} &= (q_A+q_C)\bar{x} + (q_B+q_D)\bar{x} + (q_A+q_B+q_D)x + q_Cx\\
&= \bar{x}(q_A+q_B+q_C+q_D) + x(q_A+q_B+q_C+q_D) &&\text{commutativity, then distributivity}\\
&= (\bar{x}+x)\cdot 1 &&\text{hypothesis } \textstyle\sum q = 1\\
&= 1 &&\text{complement law } x+\bar{x}=1
\end{aligned}
$$

Exactly one bit hot in, exactly one hot out — by induction from the reset state, forever.

**Binary equations**, $A=00$, $B=01$, $C=10$, $D=11$ with state $s_1s_0$. Substitute $q_A=\bar{s_1}\bar{s_0}$, $q_B=\bar{s_1}s_0$, $q_C=s_1\bar{s_0}$, $q_D=s_1s_0$ into the one-hot forms:

$$
\begin{aligned}
s_0^{+} &= x\,(q_A+q_B+q_C+q_D) &&\text{$s_0=1$ in }B,D\text{; all four have an }x\text{-edge into one of them}\\
&= x\cdot 1 = x &&\text{one-hot completeness}\\[4pt]
s_1^{+} &= \bar{x}(q_B+q_D) + x\,q_C &&\text{$s_1=1$ in }C,D\\
&= \bar{x}(\bar{s_1}s_0 + s_1s_0) + x\,s_1\bar{s_0}\\
&= \bar{x}s_0(\bar{s_1}+s_1) + x\,s_1\bar{s_0} &&\text{distributivity}\\
&= s_0\bar{x} + s_1\bar{s_0}x &&\text{complement then identity } y\cdot 1=y\\[4pt]
z &= s_1s_0x
\end{aligned}
$$

$s_0^{+}=x$ is not a coincidence: $s_0$ under this assignment *is* "the previous input bit was 1", so that flop is a one-stage shift register. Total: 2 flops, 2 LUTs — versus 4 flops and 5 LUTs one-hot, both one LUT level deep. At $N=4$ binary wins outright; the FPGA argument only turns over once $\lceil\log_2 N\rceil + k > 6$.

### Moore version

Five states: the four above plus $S_4$, entered exactly when the pattern completes, so that the output can be a function of state alone. $S_0=\varepsilon$, $S_1=1$, $S_2=10$, $S_3=101$, $S_4=1011$.

| Present | $z$ | $x=0$ | $x=1$ |
| --- | --- | --- | --- |
| $S_0$ | 0 | $S_0$ | $S_1$ |
| $S_1$ | 0 | $S_2$ | $S_1$ |
| $S_2$ | 0 | $S_0$ | $S_3$ |
| $S_3$ | 0 | $S_2$ | $S_4$ |
| $S_4$ | **1** | $S_2$ | $S_1$ |

$S_4$'s two edges are identical to $S_1$'s — after $1011$ the useful suffix is just $1$. The states differ only in output, which is precisely the split the $P_0$ round of the minimization above refused to merge.

$$
q_0^{+}=(q_0+q_2)\bar{x},\quad
q_1^{+}=(q_0+q_1+q_4)x,\quad
q_2^{+}=(q_1+q_3+q_4)\bar{x},\quad
q_3^{+}=q_2x,\quad
q_4^{+}=q_3x,\quad
z=q_4
$$

Compare $q_4^{+}=q_3x,\; z=q_4$ against the Mealy $z=q_Dx$ ($D\equiv S_3$): the same product term, with a flip-flop inserted between it and the output. **A Moore machine is its Mealy machine with the output logic registered** — one extra flop, one extra state, one extra cycle, zero glitch.

### Cycle-by-cycle trace

Input $x = 1,0,1,1,0,1,1$ (matches at bits 4 and 7, overlapping). Present state is the value held *during* the cycle.

| Cycle | $x$ | Mealy state | Mealy $z$ | Moore state | Moore $z$ |
| --- | --- | --- | --- | --- | --- |
| 1 | 1 | $A$ | 0 | $S_0$ | 0 |
| 2 | 0 | $B$ | 0 | $S_1$ | 0 |
| 3 | 1 | $C$ | 0 | $S_2$ | 0 |
| 4 | 1 | $D$ | **1** | $S_3$ | 0 |
| 5 | 0 | $B$ | 0 | $S_4$ | **1** |
| 6 | 1 | $C$ | 0 | $S_2$ | 0 |
| 7 | 1 | $D$ | **1** | $S_3$ | 0 |
| 8 | — | $B$ | 0 | $S_4$ | **1** |

Mealy fires in cycles 4 and 7 — the same cycles in which the completing input bit is present. Moore fires in 5 and 8, one cycle later, and needs an eighth cycle to report a pattern that finished during the seventh. Both fire twice, so both handle the overlap; the entire difference is the one-cycle shift, and it is a shift, not a distortion — the pulse widths and spacings are identical.

Read the one-hot Mealy equations back against cycle 4: $q_D=1$, $x=1$, so $z=q_Dx=1$ immediately, and $q_B^{+}=(q_A+q_B+q_D)x=1$ latches $B$ for cycle 5. Error in ulp: none — this machine computes a predicate exactly. The only quantity traded is the cycle in column 1.
