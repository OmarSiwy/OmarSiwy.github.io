# Plan — Digital Design → Zettelkasten

Rewrite 34 long-form notes into circuit-atomic zettel notes matching the
existing `Circuit Design/Analog Design/` vault, with a compiled Spade RTL block
and a compiled TikZ diagram in every note.

Decisions taken (2026-08-14): old notes become `S<n>` hubs · one note per
distinct circuit, **filename is the circuit's name** · every Spade block
compiled, failure blocks the write · existing prose is the source of truth, PDF
is opened for figures and gaps · each hub gets a `Choosing a …` comparison note.

Restore point before any of this: commit `72ffe35`.

## 1. Target layout

Mirrors `Circuit Design/Analog Design/` exactly — that vault is already a
zettelkasten and the reader should not have to learn two conventions.

```

  S1 Boolean Algebra.md             ← was "0.1) Boolean Algebra.md"
  Boolean Algebra/
    Full Adder.md
```

Hub `S<n>` notes hold the map and the ordered links only — every derivation
moves down into an atomic note. `S0` carries the seven-part reading order that
`Overview.md` has today.

### Naming

**The filename is the circuit's name.** Not a claim sentence — what the circuit
*buys you* is the `description:` field, and the comparison across siblings is
its own note. This departs from Analog Design's `19c2 <claim sentence>` scheme
deliberately: circuits have canonical names, concepts do not.

Two consequences, both good:

- **No ID scheme to assign.** Ordering lives in the hub, which is the structure
  note and the only place a reading order belongs.
- **The link vocabulary already exists.** `Overview.md` today writes
  `[[Kogge-Stone Tree]]`, `[[Wallace Tree]]`, `[[Barrel Shifters]]`,
  `[[Booth's Algorithm]]`. Those links start resolving instead of dangling.

Names must be globally unique — Obsidian resolves `[[Ripple-Carry Adder]]` by
basename across the whole vault. Checked: of 1625 existing notes only `Overview`
collides, and no digital circuit name clashes with an Analog note. Where a bare
name would be ambiguous across domains (digital *magnitude* comparators vs
analog *latch* comparators) the digital note takes the specific name —
`Magnitude Comparator`, `Equality Comparator` — never the bare topic word.

### The comparison note

Every hub with more than two sibling circuits gets `Choosing a <Topic>.md`
inside its folder: the trade-off table with the source's real numbers (LUT and
slice counts, logic depth, delay, DSP blocks, cycle counts) and the page each
number came from, closing with plain "pick X when …, pick Y when …". It links to
every sibling and every sibling links back to it. The hub links to it first.

### Note template

One `##` header per note (`## References`), everything else flows in the body —
matching the Analog notes.

### Who gets RTL

Three cases, and the boundary between them was established by compiling, not by
guessing. **~317 of ~340 notes carry compiled Spade.**

**`spade: verified` — the default, ~317 notes.** Anything with a clocked or
combinational structure. This deliberately includes material that reads like
theory but is really a circuit: rounding modes and HUB, sign extension, format
narrowing, Karnaugh-minimised covers, and the adder graph an ILP solver returns.
Both of these compile clean:

```spade
fn round_half_up(x: uint<16>) -> uint<9> { trunc((x + 128u16) >> 8) }
fn sext_8_to_16(x: int<8>) -> int<16> { sext(x) }
```

**`spade: not-expressible` — ~10 notes.** Spade has no latch primitive and `let`
cannot self-reference, so combinational feedback cannot be closed:

```spade
let q = if en { d } else { q };   // error: Use of undeclared name q
```

That rules out the SR latch, the transparent D latch, the cross-coupled
inverter bistable, the Muller C-element, and async fundamental-mode circuits.
Passing the feedback in as an argument compiles, but yields a mux, not a latch —
**do not do this.** These notes state the limitation with the compiler error
quoted, then show the nearest structure Spade *is* native at, which is the
edge-triggered flop the latch composes into:

```spade
entity dff(clk: clock, d: bool) -> bool {
    reg(clk) q = d;
    q
}
```

**`spade: n/a` — ~13 notes.** Genuinely no circuit: FloPoCo (a C++ generator),
ILP solver mechanics, Remez as an algorithm, discrete-time signal definitions.
Same template, no RTL block, one line saying why. These read differently from
the rest of the vault and that is correct — they are about how you *arrive* at a
circuit, not what one is.

## 2. Verified toolchain

Both harnesses tested before planning. Neither is assumed.

### Spade — `/tmp/spade-src/target/release/spade` (v0.19.0, built from source)

```sh
/tmp/spade-src/target/release/spade FILE.spade -o /dev/null --no-color
```

Exit 0 = clean. Stdlib and prelude are embedded via `include_str!` and prepended
automatically, so no flags are needed; `-o` is mandatory because there is no
`--check` mode, and `/dev/null` throws the Verilog away.

The compiler emits real diagnostics with source spans, and it earned its keep
during setup by rejecting a snippet that looked obviously right: **`^` is not
XOR on `bool` in Spade** (it is `!=`). That is the whole argument for compiling
all ~300 blocks instead of trusting a cheatsheet.

`/tmp/spade_ref/SPADE-CHEATSHEET.md` — mined from
`/tmp/spade-src/spade-compiler/stdlib/`, `swim_tests/`, and
docs.spade-lang.org; every positive snippet in it was compiled, not invented,
and `/tmp/spade_ref/verify.spade` holds all of them in one compiling file.
Authoring agents read it before writing a line.

> **Generic bodies are only checked at monomorphisation.** A generic
> `entity rca<#uint W>(...)` with a width bug in its body compiles clean until a
> concrete call site exists. Every generic snippet in a note therefore ships
> with a concrete instantiation in the file that is compiled — otherwise
> `spade: verified` is a lie. The instantiation stays in the compiled temp file;
> only the entity itself goes in the note.

The three traps most likely to bite arithmetic notes, all with compiler-quoted
evidence in the cheat sheet:

| trap | reality |
|---|---|
| operator width growth | `+`,`-` → `N+1`; `*` → `2N`; `/`,`%`,shifts → `N`. Truncating variants are the dotted forms `+.` `-.` `*.` `<<.` `>>.` |
| `as` | type *ascription*, not a cast. Converting is `as_int` / `as_uint` / `zext` / `sext` / `trunc` |
| bit access | integers are not indexable; go via `.as_bits()`, index 0 = LSB |

### TikZ — the repo's own per-block renderer

```sh
nix develop path:. --command bun build/markdown/preview-diagram.mjs block.tikz out.png
```

`flake.nix` provides `texliveFull` (TeX Live 2025), so `pdflatex` and `dvisvgm`
exist inside the dev shell — they do **not** on the bare system, which is what
the `tikzjax-verified-vocabulary` memory recorded and which is now stale.
`preview-diagram.mjs` wraps a single fence body in the exact document the site
build uses, so what previews is what ships. Tested end to end during planning:
a two-block ripple-carry sketch rendered correctly and legibly.

Agents render, then `Read` the PNG and fix label collisions — a diagram that
compiles but is unreadable is a failure.

> **A local compile does not prove Obsidian will render it.** The dev shell has
> circuitikz from TeX Live 2025; Obsidian's TikZJax bundles up to 0.9.6. The
> local check catches syntax and layout errors, not version drift. Agents stay
> inside the vocabulary already render-tested in the vault.

Vocabulary constraints carry over from the Analog build: fence language is
`tikz`, environment is `circuitikz`, no `\documentclass`, `arrows.meta` is
unavailable under Obsidian's TikZJax (use `arrows` with `latex`/`stealth`), and
`positioning`'s `right=2pt of X` needs an explicit `\usetikzlibrary` or plain
coordinates instead.

## 4. Workflow

Six phases. Phases A and B run once; C–F are the bulk and are resumable.

### Phase A — Inventory (34 agents, barrier)

One agent per source note. Reads the note plus its assigned PDF chapter (PDF
page = book page + 24, ≤20 pages per `Read` call). Returns structured JSON per
circuit: **name**, one-line "what it buys you", kind, the source headings it
comes from, book figures with page numbers, whether it is synthesizable in
Spade, and prerequisite links.

A barrier is genuinely needed here: the same circuit appears in more than one
source note (a full adder in both Boolean Algebra and Adders; the fast carry
chain in both FPGAs and Adders), and names must be checked for uniqueness across
the whole set, so dedup needs every list at once.

### Phase B — Dedup and name resolution (plain JS, no agents)

No IDs to assign, so this collapses to three checks:

1. **One owner per circuit.** A full adder is described once, in Boolean Algebra
   — Adders links to it. Same for the fast carry chain (FPGAs owns it, Adders
   links).
2. **Names globally unique** against the other 1625 vault notes; disambiguate by
   making the digital name more specific, never by adding a numeric prefix.
3. **Names match the existing link vocabulary** in `Overview.md` wherever one
   already exists, so those links go live instead of dangling.

Writes `/tmp/dd_src/inventory.json` and a human-readable `MAP.md`.

### Phase C — Stubs (one agent per hub, 34 agents)

Write every note file — every circuit, plus every `Choosing a <Topic>` — with
its frontmatter, H1, and a `ZETTEL-TODO` marker.

**This exists because of the Analog build**: when agents guessed sibling
filenames instead of linking to files that already existed, ~2200 links came out
dead. Stubs first, always. It matters more here, not less: bare circuit names
are exactly the kind of thing an agent will confidently mis-guess
(`Kogge-Stone Adder` vs `Kogge-Stone Tree`).

### Phase D — Write (pipeline over ~320 notes)

Per note, in order:

1. Read the owning source note's sections and the PDF pages for its figure.
2. Draft summary, TikZ, prose, Result, When it breaks, RTL, links, references.
3. Write the Spade block to a temp file **with a concrete instantiation
   appended**, compile, iterate until exit 0. Failure blocks the write — a note
   never ships with unverified RTL. For a `not-expressible` note, the block that
   gets compiled is the nearest-native structure, and the quoted compiler error
   is copied from a real run, never paraphrased. A `n/a` note skips this step.
4. Render the TikZ block to PNG, `Read` it, fix collisions, re-render.
5. Write the file and delete its `ZETTEL-TODO` marker.

Pipelined, not barriered — each note is independent once its stub exists.

`Choosing a <Topic>` notes run **after** their siblings in the same pipeline, so
the table quotes numbers that are already in the sibling notes rather than
inventing a second set.

### Phase E — Hubs (34 agents + 1)

Rewrite each `N.M) Topic.md` into `S<n> Topic.md`: the specification the whole
topic answers to, the map of its circuits in reading order with one line of
orientation each, a link to `Choosing a <Topic>` first, and links out to
neighbouring hubs. The trade-off table lives in the comparison note, not here —
the hub is a map. Delete the old file. Then `S0 Digital Design.md` from
`Overview.md`, preserving its seven-part reading order.

### Phase F — Link audit

Script every `[[...]]` against the file list; agents repair what does not
resolve. Then re-extract **every** ```` ```spade ```` block in the vault and
recompile the lot in one sweep — the per-note check can drift once a note is
edited by hand, and the sweep is cheap. Confirms every note has a compiled
diagram, a `spade:` value consistent with whether it has an RTL block, and that
the `not-expressible` count has not quietly grown because an agent gave up.

## 5. Resumability

Session limits killed the Analog build repeatedly, so nothing depends on a
workflow's return value.

**The vault is ground truth. A note is unfinished iff it still contains
`ZETTEL-TODO`.** `bash /tmp/dd_src/resume.sh` rebuilds the work list from only
unfinished notes and is safe to re-run until zero remain. Agents write each file
as they finish it and never batch writes to the end.

`/tmp/dd_src/` is ephemeral and regenerable: `STYLE.md` (the authoring contract
agents re-read at runtime), `MAP.md`, `inventory.json`, `resume.sh`, and the
Spade cheat sheet copied from `/tmp/spade_ref/`.

## 6. Known cost

~320 notes, each with a PDF read, a compile loop, and a render-and-look loop.
The Analog build was 1522 notes and spanned several sessions; this is roughly a
fifth of that, but still multi-session. Phases C–F are all resumable, so being
cut off costs only the note in flight.
