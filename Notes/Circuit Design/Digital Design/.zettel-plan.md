# Plan — Digital Design → Zettelkasten

Rewrite 34 long-form notes into circuit-atomic zettel notes matching the
existing `Circuit Design/Analog Design/` vault, with a compiled Spade RTL block
and a compiled TikZ diagram in every note.

Decisions taken (2026-08-14): old notes become `S<n>` hubs · one note per
distinct circuit · every Spade block compiled, failure blocks the write ·
existing prose is the source of truth, PDF is opened for figures and gaps.

---

## 1. Target layout

Mirrors `Circuit Design/Analog Design/` exactly — that vault is already a
zettelkasten and the reader should not have to learn two conventions.

```
Notes/Circuit Design/Digital Design/
  S0 Digital Design.md              ← from Overview.md, the entry hub
  S1 Boolean Algebra.md             ← was "0.1) Boolean Algebra.md"
  Boolean Algebra/
    1a A Full Adder Sums Three Bits Into a Weighted Two-Bit Result.md
    1a1 ...
  S11 Adders.md                     ← was "2.1) Adders.md"
  Adders/
    11a A Ripple-Carry Adder Chains Full Adders So Each Carry Waits...
    ...
  R1 de Dinechin and Kumm — Application-Specific Arithmetic.md
  Dienchin.pdf
```

Hub `S<n>` notes hold the map and the ordered links only — every derivation
moves down into an atomic note. `S0` carries the seven-part reading order that
`Overview.md` has today.

### Branch IDs

`<hub number><letter><digit>` — Luhmann branching, same as Analog's `19c2`.
Hub number is the `S` index, so `Adders` = S11 → `11a`, `11a1`, `11b`, …
Letter = a sibling circuit family; digit = a refinement of it. Example:

```
11e   Carry-Lookahead Resolves a Block's Carry From Generate and Propagate
11e1  Recursive Lookahead Applies the Block Rule to Blocks of Blocks
11f   A Parallel Prefix Adder Is the Carry Recurrence Reassociated as a Tree
11f1  Kogge-Stone Buys Minimum Depth With Maximum Wiring
11f2  Brent-Kung Halves the Nodes by Sweeping Up Then Down
11f3  Sklansky Trades Fanout for Depth
```

### Note template

One `##` header per note (`## References`), everything else flows in the body —
matching the Analog notes.

````md
---
title: A Ripple-Carry Adder Chains Full Adders So Each Carry Waits for the Last
description: <one line, concrete>
kind: circuit            # or: concept  (no synthesizable structure)

status: seed
spade: verified          # verified | n/a
tags: [digital, adder, carry, fpga]
---

# [ID: 11a] [Title: ...]

**One-line summary:** <exactly one sentence>

\usepackage{circuitikz}
\begin{document}

*after Fig. 5.3, p. 108*

<multi-paragraph. Bold subgoal leads ("**Turn the carry into a recurrence.**"),

**When it breaks.**
````

`kind: concept` notes (number formats, ulp and rounding definitions, error
budgets, FloPoCo, ILP modelling) keep the same shape but carry
`spade: n/a` and omit the RTL block, stating in one line why nothing is
synthesizable.

## 2. Verified toolchain

Both harnesses tested before planning. Neither is assumed.

### Spade — `/tmp/spade-src/target/release/spade` (v0.19.0, built from source)

```sh
/tmp/spade-src/target/release/spade -o /tmp/out.v snippet.spade   # exit 0 = clean
```

Stdlib and prelude are included by default. The compiler emits real diagnostics
with source spans. It already caught a plausible-looking error during setup —
`^` is **not** XOR on `bool` in Spade (use `!=`) — which is the argument for
compiling all ~300 blocks rather than trusting a cheatsheet.

A cheat sheet mined from `/tmp/spade-src/spade-compiler/stdlib/`,
`swim_tests/`, and docs.spade-lang.org is being written to
`/tmp/spade_ref/SPADE-CHEATSHEET.md`; authoring agents read it before writing.

### TikZ — the repo's own per-block renderer

```sh
nix develop path:. --command bun build/markdown/preview-diagram.mjs block.tikz out.png
```

`flake.nix` provides `texliveFull`, so LaTeX exists inside the dev shell (it does
not on the bare system). `preview-diagram.mjs` wraps a single fence body in the
exact document the site build uses, so what previews is what ships. Agents
render, then `Read` the PNG and fix label collisions — a diagram that compiles
but is unreadable is a failure.

Vocabulary constraints carry over from the Analog build: fence language is
`tikz`, environment is `circuitikz`, no `\documentclass`, `arrows.meta` is
unavailable under Obsidian's TikZJax (use `arrows` with `latex`/`stealth`), and
`positioning`'s `right=2pt of X` needs an explicit `\usetikzlibrary` or plain
coordinates instead.

## 4. Workflow

Six phases. Phases A and B run once; C–F are the bulk and are resumable.

### Phase A — Inventory (34 agents, barrier)

One agent per source note. Reads the note plus its assigned PDF chapter (PDF
page = book page + 24, ≤20 pages per `Read` call). Returns structured JSON per
circuit: slug, claim title, kind, source headings, book figures with page
numbers, whether it is synthesizable in Spade, and prerequisite links.

A barrier is genuinely needed here: the same circuit appears in more than one
source note (a full adder in both Boolean Algebra and Adders; a carry chain in
both FPGAs and Adders), so dedup and ID assignment need every list at once.

### Phase B — Dedup and ID assignment (plain JS, no agents)

Merge duplicates to a single owning hub, assign `<hub><letter><digit>` IDs,
write `/tmp/dd_src/inventory.json` and a human-readable `MAP.md`.

### Phase C — Stubs (one agent per hub, 34 agents)

Write every note file with its frontmatter, H1, and a `ZETTEL-TODO` marker.
**This exists because of the Analog build**: when agents guessed sibling
filenames instead of linking to files that already existed, ~2200 links came out
dead. Stubs first, always.

### Phase D — Write (pipeline over ~320 notes)

Per note, in order:

1. Read the owning source note's sections and the PDF pages for its figure.
2. Draft intro, TikZ, prose, Result, When it breaks, RTL, links, references.
3. Write the Spade block to a temp file, compile it, iterate until exit 0.
   Failure blocks the write — a note never ships with unverified RTL.
4. Render the TikZ block to PNG, `Read` it, fix collisions, re-render.
5. Write the file and delete its `ZETTEL-TODO` marker.

Pipelined, not barriered — each note is independent once its ID exists.

### Phase E — Hubs (34 agents + 1)

Rewrite each `N.M) Topic.md` into `S<n> Topic.md`: specification, the map of its
circuits in reading order with one line of orientation each, the trade-off table
comparing them with the book's real numbers and pages, and links out. Delete the
old file. Then `S0 Digital Design.md` from `Overview.md`.

### Phase F — Link audit

Script every `[[...]]` against the file list; agents repair what does not
resolve. Also confirms every note has a compiled diagram and a `spade:` value.

## 5. Resumability

Session limits killed the Analog build repeatedly, so nothing depends on a
workflow's return value.

**The vault is ground truth. A note is unfinished iff it still contains
`ZETTEL-TODO`.** `bash /tmp/dd_src/resume.sh` rebuilds the work list from only
unfinished notes and is safe to re-run until zero remain. Agents write each file
as they finish it and never batch writes to the end.

`/tmp/dd_src/` is ephemeral and regenerable: `STYLE.md` (the authoring contract
agents re-read at runtime), `MAP.md`, `inventory.json`, `resume.sh`, and the
Spade cheat sheet copied from `/tmp/spade_ref/`.

## 6. Known cost

~320 notes, each with a PDF read, a compile loop, and a render-and-look loop.
The Analog build was 1522 notes and spanned several sessions; this is roughly a
fifth of that, but still multi-session. Phases C–F are all resumable, so being
cut off costs only the note in flight.
