# Symmetric Table of Offsets

A table of offsets re-centred on the midpoint of its segment becomes an *odd* function of the low sub-word $B$, so only half of it needs storing and the other half is generated by two rows of XOR gates.

*after Fig. 17.8, p. 507; the book's figure uses $\beta=\gamma=3$*

**Move the initial value to the middle of the segment.** In the plain [[Bipartite Table Method]] the TIV holds $f$ at the *left* endpoint $x_l(A)=2^{-\alpha}A$ and the TO holds the non-negative ramp $s(C)\times2^{-\alpha}B$ for $B\in[0,2^{\beta})$. Re-anchor instead on the midpoint, taking

$$\mathrm{TIV}^*(A)=\frac{f(x_l(A))+f(x_r(A))}{2}$$

which is also the fill that equalises the two extreme approximation errors of the segment (Eq. 17.22, p. 514). The offsets then have to run either side of zero, so read the $\beta$-bit word $B$ as **two's complement**, $B\in[-2^{\beta-1},2^{\beta-1}-1]$, and the tabulated quantity becomes

$$\mathrm{TO}^*(C,B)=s(C)\times 2^{\ell_R+p}\left(B+\tfrac12\right)\qquad\text{(Eq. 17.23, p. 514)}$$

The $+\tfrac12$ is not cosmetic: it places the $2^\beta$ sample points symmetrically about the centre without any of them landing *on* it, which is what makes the two halves exact mirror images rather than one half plus a shared middle entry. Widths: $C$ is $\gamma$ bits, $B$ is $\beta$ bits, and the tabulated value is $m_i-\ell_R+g+1$ bits signed before symmetry is exploited, where $m_i=\lceil\log_2 r_i\rceil$ is the MSB weight from Eq. (17.35) and $g$ is the guard-bit count (format conventions in [[Number Formats]], the ulp budget in [[Error Accuracy]]).

**The centring turns the table into an odd function of $B$.** Apply the two's-complement identity $-x=\bar x+1$ in the rearranged form $\bar B=-B-1$, valid for the $\beta$-bit bitwise complement of a two's-complement word. Substituting into Eq. (17.23):

$$\mathrm{TO}^*(C,\bar B)=s(C)\,2^{\ell_R+p}\left(-B-1+\tfrac12\right)=-\,s(C)\,2^{\ell_R+p}\left(B+\tfrac12\right)=-\,\mathrm{TO}^*(C,B)$$

This is an identity, not an approximation — it holds before any rounding, for every $C$, because $\mathrm{TO}^*$ is **linear in $B$ with the half-ulp shift as its only constant**. Half the entries are therefore redundant, and the redundancy is a negation, which is the cheapest map two's complement offers.

**Complementing the address costs $\beta-1$ XOR gates.** Let $b_{\beta-1}$ be the MSB of $B$, i.e. its sign. If $b_{\beta-1}=0$ the argument is already in the stored half and is addressed by the low $\beta-1$ bits directly. If $b_{\beta-1}=1$ then $\bar B$ has sign bit $0$ and low bits $\overline{B_{\beta-2..0}}$, so in both cases the stored-half address is

$$\mathrm{addr}=B_{\beta-2..0}\oplus\left(b_{\beta-1}\right)^{\beta-1}$$

with the sign bit simply fanned out across the row — $\beta-1$ two-input XOR gates and no other logic. The TO is now addressed by $\gamma+\beta-1$ bits: **one input bit won**, $2^{\gamma+\beta}\to2^{\gamma+\beta-1}$ entries.

**Complementing the output is free only because the tables are HUB.** Negating a plain two's-complement word $y$ needs $\bar y+1$, and that trailing $+1$ is a carry into the summation — an extra bit-heap entry per TO, or worse, an incrementer. HUB format removes it. The tables are filled at precision $\ell_R-g$ with a half-ulp implicitly set at weight $\ell_R-g-1$, so the value a stored word $y$ denotes is $(y+\tfrac12)2^{\ell_R-g}$, and

$$-\left(y+\tfrac12\right)=\left(-y-1\right)+\tfrac12=\bar y+\tfrac12$$

so **bitwise complement is exact negation, with no correction term at all** (p. 517 — this is the stated reason §17.2.7 chooses HUB rounding for all $m$ of the TOs; see [[HUB Table Filling]] and [[Rounding]]). The stored half is an *unsigned* magnitude of $w=m_i-\ell_R+g$ bits; what leaves the block is $w+1$ bits signed, whose MSB is $b_{\beta-1}$ itself — a wire, not a gate. So the output row is $w$ XOR gates, not $w+1$. **One output bit won.**

**Count what the two rows bought.** Without symmetry the TO occupies $2^{\gamma_i+\beta_i}(m_i-\ell_R+g+1)$ bits; with it, $2^{\gamma_i+\beta_i-1}(m_i-\ell_R+g)$ bits (p. 517). The ratio is

$$\frac{2^{\gamma+\beta}(w+1)}{2^{\gamma+\beta-1}\,w}=2\cdot\frac{w+1}{w}$$

— a factor of $2$ from the address bit, plus a few percent to $25\%$ more from the output bit depending on how narrow $w$ is. The price is $(\beta-1)+w$ XOR gates and two extra gate delays, one in front of the address decoder and one behind the table output.

> [!warning] The long-form note and the inventory both call this a "4× reduction in stored bits". The formulas do not give that: $2(w+1)/w$ is $2.5\times$ at $w=4$ and tends to $2\times$ as $w$ grows. The book claims only that symmetry "halves the size of the TO" (p. 507) and "wins one bit on input and also one bit on output" (p. 517). Corrected here and in this note's `description`.

**Symmetry is a constraint on how the table may be filled.** Das Sarma and Matula's original bipartite paper proposed fitting the TO to an "average curve" rather than a line, which improves the *average* error at no cost in maximum error — but an average-curve fit is not odd in $B$, the two halves stop being mirror images, and the $2\times$ evaporates. The book rejects the idea for exactly that reason (p. 507). The same reasoning applies to any per-entry-optimised fill: symmetry is worth more than a fractional accuracy gain, so it is treated as a hard structural constraint on every candidate decomposition ([[Choosing a Table Method]]).

**On FPGAs, count LUTs, not bits.** A $2^k\times n$ ROM costs $2^{\max(k-\lambda,0)}\times n$ LUTs on a $\lambda$-input device, so shaving the address bit genuinely halves the LUT count *while $k>\lambda$*, and shaving the output bit removes $2^{\max(k-\lambda,0)}$ LUTs. Below $2^\lambda$ entries a table is free real estate — a $2^{\lambda-1}\times n$ ROM still costs $n$ LUTs with half of each wasted (p. 492) — so on a small TO the address saving buys nothing while the $(\beta-1)+w$ XOR gates still consume fabric. On an ASIC the standard-cell cost model $2^{0.65\min(k,n)}2^{0.19|k-n|}$ (Eq. 16.1, p. 491) is symmetric in $k$ and $n$, so both won bits count equally and the XORs are noise against a decoder.

$$\boxed{\ \mathrm{TO}^*(C,\bar B)=-\,\mathrm{TO}^*(C,B)\quad\Longrightarrow\quad 2^{\gamma+\beta}(w+1)\ \text{bits}\ \longrightarrow\ 2^{\gamma+\beta-1}\,w\ \text{bits},\qquad w=m_i-\ell_R+g\ }$$

**When it breaks.**

- $\beta=1$: the stored half is a single entry, the input XOR row has $\beta-1=0$ gates, and the "table" is a constant. Nothing left to compress.
- Tables at or below $2^\lambda$ entries on an FPGA: halving the address frees no LUT, so the XOR rows are pure overhead. This is invisible in the book's bit-count objective and is the standard reason a bit-optimal decomposition is not LUT-optimal.
- Round-to-nearest instead of HUB: negation reverts to $\bar y+1$ and the trailing $+1$ has to enter the summation. It is not a constant, because the sign bit varies with the input, so it costs a real bit-heap column rather than a free one.
- Non-linear TO fills — average-curve fitting, or an entry-by-entry numerical search — are not odd in $B$ and forfeit the halving entirely.
- Order-two and higher table methods: the correction tables of [[ATA, Addition-Table-Addition]] and [[STAM, Symmetric Table Addition Method]] carry their own symmetry argument; it does not follow from this one, which is a property of the *linear* model only.
- Latency-critical designs at small $\gamma+\beta$: two XOR levels wrapped around a table whose own delay is a couple of LUT delays is a large relative latency hit for a $2\times$ area win.

**RTL (Spade).**

```spade
// Stored half of a table of offsets: beta = 4, one slope, HUB magnitudes.
// Entry a holds mag(a) with mag(a) + 1/2 = s * (a + 1/2); here s = 3.
fn to_half(a: uint<3>) -> uint<5> {
    let t: [uint<5>; 8] = [1, 4, 7, 10, 13, 16, 19, 22];
    t[a]
}

entity sym_to4(b: uint<4>) -> int<6> {
    // b read as two's complement: its MSB says which side of the centre we are on.
    let s = b.msb();
    // input XOR row: beta-1 gates, the sign bit fanned out as the second operand
    let addr: uint<3> = trunc(b) ^ [s; 3].as_uint();
    let half: uint<6> = zext(to_half(addr));
    // output XOR row: in HUB format bitwise complement is exact negation
    (half ^ [s; 6].as_uint()).as_int()
}
```

`s` is the red control bus of the diagram, and `[s; 3].as_uint()` / `[s; 6].as_uint()` are the two XOR rows — written as a replication of one bit precisely because that is a fanout in silicon, not a mux. `to_half` is the half table; the drawing's $2^{\gamma+\beta-1}$ entries collapse to $2^{\beta-1}$ here because a single $C$ is hard-wired. The block is purely combinational, and the widths grow $4\to3$ at the address and $5\to6$ at the output, the extra output bit being the sign that costs no gate. Synthesis will not build the array as a ROM at this size — it will collapse `to_half` into logic and very likely absorb the output XOR row into the same LUTs, which is the one thing the drawing cannot show.

Exhaustively checked over all 16 inputs plus 3000 random vectors against the behavioural reference $\mathrm{out}=3B+1$ (equivalently $2\,\mathrm{out}+1=s\,(2B+1)$ in half-ulps), including the asymmetric pair $b=\texttt{0001}\mapsto+4$ and $b=\texttt{1000}\mapsto-23$ that a bit-reversed or unmirrored address would fail.
