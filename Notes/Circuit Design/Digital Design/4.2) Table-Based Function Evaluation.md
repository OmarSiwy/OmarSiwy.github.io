**Input.** One unsigned fixed-point word $X\in[0,1)$ of $w_X$ bits, $\ell_X=-w_X$ (format conventions in [[1.1) Number Formats]]; the domain and range preparation is [[4.1) Fixed-Point Function Approximation]]).
**Output.** $R(X)$, a fixed-point word of LSB $\ell_R$, approximating a continuous, differentiable $f$ with bounded derivatives.
**Accuracy.** *Faithful* (last-bit accurate): $|R(X)-f(X)|<2^{\ell_R}$, i.e. strictly under one ulp. That single ulp is the entire budget and it gets split three ways below (see [[1.2) Error Accuracy]]).
**Optimized for.** Total table bits first — table size is $2^{w_X}$ and everything else is linear, so the exponential term dominates. Adders are the currency we spend to buy that reduction; latency and adder count are the secondary objectives.
**Not optimized for.** Multiplier-free is a *hard constraint* here, not an objective: the whole family exists to avoid the multiplier that a naive linear interpolation would need.

## Where the two tables come from

A plain ROM ([[4.1) Fixed-Point Function Approximation]]) stores $2^{w_X}$ values of $w_R$ bits. Exponential in $w_X$, linear in $w_R$ — so the fight is always over $w_X$.

Split the input word into an $\alpha$-bit head and a $\beta$-bit tail, $\alpha+\beta=w_X$:

$$X = A + 2^{-\alpha}B,\qquad A\in 2^{-\alpha}\mathbb{Z}\cap[0,1),\quad B\in[0,1)\ \text{on}\ \beta\ \text{bits}$$

**Taylor at $A$**, with the remainder in Lagrange form:

$$f(A+2^{-\alpha}B)=f(A)+2^{-\alpha}B\,f'(A)+\tfrac12\left(2^{-\alpha}B\right)^2 f''(\xi),\qquad \xi\in(A,X)$$

The quadratic term is bounded by $\tfrac12 2^{-2\alpha}\max|f''|$. Forcing it under the half-ulp share $2^{\ell_R-1}$ with $\ell_R\approx-w_X$ gives

$$\boxed{\alpha\gtrsim w_X/2}$$

which is the **intrinsic lower bound on $\alpha$ for any order-one scheme** (p. 523). Keep only the two leading terms and you have a *uniform piecewise linear approximation*: tabulate $f(A)$ and $f'(A)$, then multiply. Two tables of $2^\alpha$ entries **and a multiplier**, which is exactly what we refuse to pay.

The bipartite observation is that $f'$ is *slowly varying* — that is the same hypothesis as "$f''$ bounded" we just used. So round $A$ down to its $\gamma$ most significant bits, $C$, with $\gamma<\alpha$, and use one slope $s(C)$ for the whole group of $2^{\alpha-\gamma}$ consecutive segments. The extra error is

$$\left|2^{-\alpha}B\left(f'(A)-s(C)\right)\right| \;\le\; 2^{-\alpha}\cdot 2^{-\gamma}\max|f''|$$

**by the mean value theorem applied to $f'$** over an interval of width $2^{-\gamma}$. Under $2^{\ell_R-1}$ this asks for $\alpha+\gamma\gtrsim w_X$. Drawn, one group of segments looks like this:

> [!important] The decoupling is the whole trick
> The value table is addressed by $\alpha$ bits; the *slope* table only needs $\gamma<\alpha$ bits, because the slope changes more slowly than the value. And since the slope table is indexed by $C$ alone, the product $s(C)\times 2^{-\alpha}B$ has only $2^{\gamma+\beta}$ distinct values — **so tabulate the product, not the slope, and the multiplier disappears with it.**
> $$f(X)\;\approx\;\underbrace{f(A)}_{\text{TIV},\;2^{\alpha}\ \text{entries}}\;+\;\underbrace{s(C)\times 2^{-\alpha}B}_{\text{TO},\;2^{\gamma+\beta}\ \text{entries}}$$
> **TIV** = table of initial values, **TO** = table of offsets. One exponential table became two smaller ones plus one addition.

Now pick the sizes. Minimise $2^{\alpha}+2^{\gamma+\beta}$ subject to the two constraints just derived, taken tight — $\alpha+\beta=w_X$ (the split is exhaustive) and $\alpha+\gamma=w_X$ (accuracy). The second forces $\gamma=\beta$, so the cost is $2^\alpha+2^{2(w_X-\alpha)}$, minimised when the exponents match:

$$\alpha=2(w_X-\alpha)\quad\Longrightarrow\quad \alpha\approx\tfrac{2w_X}{3},\qquad \beta\approx\gamma\approx\tfrac{w_X}{3}$$

which is precisely the rule of thumb previous authors reached by Taylor analysis (p. 506). Note it satisfies $\alpha\ge w_X/2$ comfortably. Entry count drops from $2^{w_X}$ to $\approx 2\cdot2^{2w_X/3}$ — a $2^{w_X/3}/2$ factor, so the win grows exponentially with precision. These are starting points only; the real parameters come out of an exhaustive search (below), because the constants $\max|f''|$ matter.

## Lossless differential table compression

LDTC is the odd one out in this chapter: it is **not** an approximation technique. It replaces a table $T$ with two smaller tables and an addition whose result is bit-for-bit the original value. It therefore composes with everything else, and is presented first because the multipartite method uses it on its own TIV.

### Applicability

$T:A\mapsto R$ with $w_A$ address bits and $w_R$ output bits compresses if **values at neighbouring addresses vary little relative to the full output range**. Tabulating a regular function gives this for free, but the property is about the *discrete table*, not the mathematics: the coefficient tables produced by a numerical minimax optimisation compress well even though no real function samples them and one of them is not even monotonic (p. 498). The book's honest formal definition is circular — "$T$ compresses if Algorithm 17.1 succeeds".

Uses elsewhere in the book: polynomial coefficient tables ([[4.3) Polynomial Approximation]]), the sine/cosine table of the sine/cosine table of Fig. 20.11, the exp table of Chap. 22. The [[3.1.2) KCM, Table-Based Constant Multiplication]] tables would qualify too, but KCM has already spent that redundancy (p. 499).

### Parameter space

Sub-sample $T$ by a factor $2^s$. The **sub-sampling table** $T_{ss}:B\mapsto H$ has $2^{w_A-s}$ entries of $w_H$ bits; the **difference table** $T_d:A\mapsto L$ keeps all $2^{w_A}$ entries but only $w_L$ bits, because it stores local variation. A *slice* is a run of $2^s$ consecutive values reconstructed from one $T_{ss}$ entry.

$$T(A)=T_{ss}\!\left(\lfloor A/2^s\rfloor\right)+T_d(A),\qquad v = w_H+w_L-w_R \ \ \text{(overlap bits)}$$

Compression happens as soon as $2^{w_A-s}w_H+2^{w_A}w_L < 2^{w_A}w_R$. Two refinements, in order of discovery:

- Hsiao's naive version leaves $2^s$ systematic zeros in $T_d$ (one per slice). Removing the $w_R-w_L$ LSBs from $T_{ss}$ reclaims those, shrinking $T_{ss}$, at the risk of one overflow bit appearing in $T_d$ (p. 499).
- That overflow bit is expensive — it is paid $2^{w_A}$ times, whereas keeping $k$ extra output bits in $T_{ss}$ costs only $k\cdot2^s$ bits. Hence the parameter triplet $(s,w_H,w_L)$ is enumerated rather than derived (p. 500).

### The optimization algorithm and validity test

Algorithm 17.1 enumerates $(s,w_H,w_L)$, and — because the cost function is cheaper to evaluate than validity — **filters by cost first, checks validity second**, keeping the cheapest valid vector. Validity (Algorithm 17.2) is itself exhaustive but cheap: for each slice, take $M=\max$, $m=\min$, set $H = m - (m\ \&\ (2^{w_R-w_H}-1))$ (the $w_H$ upper bits of $m$), and reject if $M-H\ge 2^{w_L}$ — one slice that does not fit kills the vector. Cost is proportional to $2^{w_A-s}$, not $2^{w_A}$, since max/min per slice are memoised per $s$. Exploration is "almost instantaneous for any size for which tabulation is practical" (p. 501).

### Cost function

$c(w_A,s,w_H,w_L)$ = cost of $T_{ss}$ + cost of $T_d$ + cost of the addition, with table cost technology-dependent (see the FPGA section below).

The addition is cheaper than it looks. As a standalone adder it is only $w_H$ bits wide — the low $w_R-w_H$ bits of the sum are just $L$'s bits, unchanged. But in most real uses the table output feeds a compressor tree anyway, so the reconstruction is merged into a [[2.3) Sums of Weighted Bits|bit heap]] and **adds only the $v$ overlap bits to the heap** (Fig. 17.2, p. 502). If those $v$ bits do not force an extra compression stage, the delay overhead is exactly zero.

### Evaluation

Compression ratios (integrated into [[7.1) FloPoCo]] behind `tableCompression`) of $0.5$–$0.8$ are typical (20–50% savings); the best reported is $0.36$ (p. 502). LDTC works best when $w_R$ and $w_A$ are close, since $T_d$ is the big table and it has few output bits when $w_R\approx w_A$. The optimal overlap is usually $v=2$, occasionally $3$.

## Multipartite methods

### Applicability

Unlike LDTC these are genuinely approximate, and they need **continuity, differentiability, and a well-bounded derivative**. $\sqrt{x}$ on $[0,1)$ fails outright: the vertical tangent at $0$ means $\max|f'|=\infty$ and, worse, $\max|f''|=\infty$, which is what the derivation above actually depends on. The fix is function-specific [[4.3.2) Range Reduction|range reduction]] — evaluate $\sqrt{x}$ on $[1,2)$ instead, transported to $2(\sqrt{1+x}-1)$ on $[0,1)$ by change of variable, which is smooth and bounded (Fig. 17.3, p. 503). Historically these methods were *invented* for reciprocal and reciprocal square root, so this is the normal way to use them, not a caveat.

### Exploiting symmetry

Each linear segment is trivially symmetric about its centre. Store the TO for a half-segment only and generate the other half by negation: in two's complement, $-x=\bar x+1$, and the $+1$ is a constant absorbed elsewhere, so **two rows of XOR gates** implement the symmetry (Fig. 17.8, p. 507). The MSB of $B$ drives the XORs and stops being a table address bit.

This wins **one input bit and one output bit**: the TO drops from $2^{\gamma+\beta}(m_0-\ell_R+g+1)$ to $2^{\gamma+\beta-1}(m_0-\ell_R+g)$ — a 4× reduction in stored bits for a handful of gates. Das Sarma and Matula's original "average curve" TO fit would give slightly better average error, but it destroys the symmetry and hence this 4×, so it is not used (p. 507).

### From bipartite to multipartite: splitting the TO

The TO computes $\mathrm{TO}(C,B)\approx s(C)\times B$, which is **linear in $B$**. So split $B$ itself:

$$B = B_0 + 2^{\beta_0}B_1+\dots+2^{\beta_0+\dots+\beta_{m-2}}B_{m-1},\qquad p_0=0,\ \ p_i=\textstyle\sum_{j<i}\beta_j$$

and **by linearity of $s(C)\times{\cdot}$ distributing over that sum**,

$$\mathrm{TO}(C,B)=s(C)\times\sum_{i=0}^{m-1}2^{p_i}B_i=\sum_{i=0}^{m-1}\underbrace{s(C_i)\times 2^{p_i}B_i}_{\mathrm{TO}_i(C_i,B_i)}$$

$m$ tables of $2^{\gamma_i+\beta_i}$ entries instead of one of $2^{\gamma+\beta}$, at the price of $m-1$ extra additions. Two trade-offs follow (p. 509): a **cost** trade-off (more adders, less table) and an **accuracy** trade-off — the identity above is exact, but each of the $m$ tables now carries its own discretization error and they sum.

The generalisation that beats everyone: because $\mathrm{TO}_i$ and $\mathrm{TO}_j$ differ by the factor $2^{p_j-p_i}$, the low-order $\mathrm{TO}_i$ are *more accurate than they need to be*. Spend that slack by giving each $\mathrm{TO}_i$ its **own** $\gamma_i$ — a rougher slope for the tables that contribute less. A decomposition is then

$$\mathcal{D}=\{\alpha,\beta,m,(\gamma_i,p_i,\beta_i)_{i=0\dots m-1}\}$$

### Error analysis: splitting one ulp three ways

Define the virtual real-valued approximation $\widetilde{f^{\mathcal D}}(X)=\mathrm{TIV}^*(A)+\sum_i\mathrm{TO}^*_i(C_i,B_i)$ (starred = infinitely precise). Then, **by inserting and cancelling $\widetilde{f^{\mathcal D}}$**,

$$\delta_{\text{total}} = \underbrace{R-\widetilde{f^{\mathcal D}}}_{\delta_{\text{round}}}+\underbrace{\widetilde{f^{\mathcal D}}-f}_{\delta_{\text{approx}}},\qquad \delta_{\text{round}}=\underbrace{R-S}_{\text{final round}}+\underbrace{S-\widetilde{f^{\mathcal D}}}_{\text{table filling}}$$

where $S$ is the extended-precision sum before the final rounding — three terms, one ulp between them.

**(1) Approximation error.** Assume $f$ monotonic with monotonic derivative (convex or concave) — true of every function studied, after range reduction. On the group of segments sharing one $C_i$, the extreme segments $[x_{ll},x_{lr}]$ and $[x_{rl},x_{rr}]$ are where the fixed slope $s_i$ fits worst. With the initial value free (the TIV supplies it per $A$), the residual on a segment of chord slope $\sigma$ is $\pm(\sigma-s_i)\Delta_i/2$. Balancing $\delta_{ll}=-\delta_{lr}=-\delta_{rl}=\delta_{rr}$ gives

$$s_i(C_i)=\frac{\sigma_l+\sigma_r}{2}=\frac{f(x_{lr})-f(x_{ll})+f(x_{rr})-f(x_{rl})}{2\Delta_i},\qquad \delta_i(C_i)=\frac{(\sigma_r-\sigma_l)\Delta_i}{4}$$

**the optimal slope is the average of the two extreme chord slopes** — unsurprising, and better than the midpoint slope used by earlier work. The geometry is fixed by

$$\Delta_i=2^{\ell_X+p_i}(2^{\beta_i}-1),\quad x_{ll}=2^{-\gamma_i}C_i,\quad x_{lr}=x_{ll}+\Delta_i,\quad x_{rl}=x_{ll}+2^{-\gamma_i}-2^{\ell_X+p_i+\beta_i},\quad x_{rr}=x_{rl}+\Delta_i$$

By convexity the worst $C_i$ is an endpoint, so $\overline{\delta_i^{\mathcal D}}=\max\left(|\delta_i(0)|,\;|\delta_i(2^{\gamma_i}-1)|\right)$ and $\overline{\delta_{\text{approx}}}=\sum_i\overline{\delta_i^{\mathcal D}}$. A few floating-point operations per table — cheap enough to sit inside an exhaustive search.

> [!warning] Two typos in the printed equations
> Eq. (17.12), p. 513 prints $\delta_i=\frac{f(x_{lr})-f(x_{ll})+f(x_{rr})-f(x_{rl})}{4}$, which is $s_i\Delta_i/2$ — a slope, not an error, and it is numerically ~40× too large. The signs of the first pair must be flipped, as derived above. Eq. (17.23), p. 514 prints $\mathrm{TO}^*_i=s(C_i)\times2^{\ell_R+p_i}(B_i+\tfrac12)$; it must be $2^{\ell_X+p_i}$, since Eq. (17.34) states the range of that table is exactly $|s_i(C_i)\Delta_i|$. Both corrections were confirmed numerically in the worked example.

**(2) Table-filling error.** Rounding each ideal value to $\ell_R$ directly would cost $2^{\ell_R-1}$ per table — the budget is blown before the second table. So fill every table to $\ell_R-g$, $g$ **guard bits**. With round-to-nearest each of the $m+1$ tables errs by at most $2^{\ell_R-g-1}$, hence $|\delta_{\text{tables}}|\le(m+1)2^{\ell_R-g-1}$, arbitrarily small in $g$.

**(3) Final rounding.** Rounding $S$ from $\ell_R-g$ down to $\ell_R$ costs $2^{\ell_R-1}$; the HUB trick improves it to $2^{\ell_R-1}(1-2^{-g})$.

**Solve for $g$.** Faithfulness demands the three sum to less than $2^{\ell_R}$:

$$2^{\ell_R-1}-2^{\ell_R-g-1}+(m+1)2^{\ell_R-g-1}+\overline{\delta_{\text{approx}}}<2^{\ell_R} \;\Longleftrightarrow\; m\,2^{\ell_R-g-1}<2^{\ell_R-1}-\overline{\delta_{\text{approx}}}$$

and taking $\log_2$ of both sides,

$$\boxed{\,g=\left\lceil \ell_R-1+\log_2 m-\log_2\!\left(2^{\ell_R-1}-\overline{\delta_{\text{approx}}}\right)\right\rceil\,}$$

Read it as a budget: the final rounding claims half an ulp outright; $\overline{\delta_{\text{approx}}}$ eats into the other half; whatever remains is divided among $m$ tables, and $g$ is how many bits you must buy to fit. **If $\overline{\delta_{\text{approx}}}\ge2^{\ell_R-1}$ the decomposition is rejected before $g$ is even computed** — no amount of guard bits rescues a bad split. In practice $g$ can very often be decremented by one and stay faithful, because worst-case rounding is not actually attained in every table; FloPoCo keeps the safe value (p. 516).

### Computing the sizes of the sub-tables

The table sizes fall directly out of that split, since $g$ is now known.

$$\text{TIV}:\ 2^{\alpha}\,(w_R+g)\ \text{bits},\qquad w_R=m_R-\ell_R+1$$

For $\mathrm{TO}_i$, the range is exactly $|s_i(C_i)\Delta_i|$, maximal at an endpoint by convexity again:

$$r_i=\max\left(|s_i(0)\Delta_i|,\ |s_i(2^{\gamma_i}-1)\Delta_i|\right),\quad m_i=\lceil\log_2 r_i\rceil,\quad \text{TO}_i:\ 2^{\gamma_i+\beta_i}(m_i-\ell_R+g+1)\ \text{bits, or}\ 2^{\gamma_i+\beta_i-1}(m_i-\ell_R+g)\ \text{with symmetry}$$

### Filling the tables using HUB format

There are two ways to round to $\ell_R-g$ with error under $2^{\ell_R-g-1}$: round-to-nearest, or [[1.2.1) Rounding|HUB]] — truncate to $\ell_R-g$ with an *implicit* 1 at position $\ell_R-g-1$. HUB is chosen for all $m$ TOs because **the opposite of a HUB number is its bitwise complement**, which is exactly what the symmetry XORs need — no $+1$ correction.

The implicit half-ulps must eventually be paid, and here is the accounting trick: *any even number of half-ulps is a whole number of ulps and can be folded into one table's constant, for free*. So

- $m$ **even**: use HUB for the TIV too; add $m/2$ ulps to every TIV entry; one implicit half-ulp (the TIV's own) survives into the sum.
- $m$ **odd**: round the TIV to nearest instead; explicit $(m-1)/2$ ulps added to each TIV entry; again one half-ulp survives.

Either way exactly one half-ulp remains, and adding $2^{\ell_R-1}$ into every TIV entry at fill time makes the **final rounding a pure truncation — zero hardware**. The tables are filled with

$$\mathrm{TO}_i=\left\lfloor 2^{-\ell_R}\mathrm{TO}^*_i\right\rfloor,\qquad \mathrm{TIV}(A)=\left\lfloor 2^{-\ell_R}\mathrm{TIV}^*(A)+c+2^{g-1}\right\rfloor,\quad c=\begin{cases}\tfrac{m-1}{2}&m\ \text{odd}\\[2pt]\tfrac{m}{2}&m\ \text{even}\end{cases}$$

### Errorless compression of the TIV

The TIV is $2^\alpha(w_R+g)$ bits and is almost always the dominant term. It is also a table of a smooth function sampled at neighbouring addresses — the textbook case for LDTC. Applying §17.1 to it splits it into $\mathrm{TIV}_{ss}+\mathrm{TIV}_{\text{diff}}$ at **zero** accuracy cost, so it slots into the search without touching the error analysis at all (Fig. 17.13, p. 518).

### The full optimization algorithm

Algorithm 17.3 (p. 519), one pass per candidate decomposition:

1. Enumerate $\mathcal{D}=\{\alpha,\beta,m,(\gamma_i,p_i,\beta_i)\}$.
2. Compute $\overline{\delta_{\text{approx}}}$; **reject if $\ge2^{\ell_R-1}$** (independent of $g$, so this is the cheap early filter).
3. Compute $g$.
4. Compute total table bits, TIV compression included.
5. Keep the smallest.

Naively exponential, cut to seconds for 24-bit operands (the largest size where multipartite makes sense at all) by three prunings:

- $\overline{\delta_i^{\mathcal D}}$ grows as $\gamma_i$ shrinks, so there is a $\gamma_{\min}(p_i,\beta_i)$ below which the table can never be faithful — tabulate it once.
- $p_{i+1}=p_i+\beta_i$ constrains the $(p_i,\beta_i)$ enumeration; $\gamma_{\min}<\gamma_i<\alpha$ constrains the rest.
- $\overline{\delta_i^{\mathcal D}}$ depends only on $(p_i,\beta_i,\gamma_i)$, so precompute a $24^3=13\,824$-entry array of doubles once per function.

$m$ is a user knob trading tables against adders; FloPoCo sweeps $m\in[1,7]$.

**Concrete run** (p. 520), 16-bit in / 16-bit out $\sin$: $m$ from 1 to 3, with 5 valid decompositions at $m=1$, 39 at $m=2$, 24 at $m=3$; $g$ from 1 to 5. Best is $m=3$ with a compressed TIV of $7\cdot2^6+13\cdot2^9$ bits and TOs of $9\cdot2^9+7\cdot2^8+5\cdot2^8$ bits — **14 784 bits against 1 048 576 for the plain table, a factor 70**, found in under a second.

The automatic result can be beaten by ~15% (p. 520) because the algorithm assumes worst-case rounding in every table, which with only $2^5$–$2^9$ entries per table is statistically pessimistic. Manual decrements of $g$ or of the $\gamma_i$, verified by exhaustive check, recover it:

| $\sin(\pi x/4)$, $\ell_X=\ell_R=-16$, $m=4$ | total bits | max measured error |
| --- | --- | --- |
| automatic | 7808 | 0.915 ulp |
| hand-tuned $\gamma_i$, $g$ | **6912** (−11.5%) | 0.939 ulp |

*Table 17.2, p. 521.* Note the second row has a **method** error above 0.5 ulp that lucky rounding compensates — only defensible because the final implementation exhaustively evaluates $\delta_{\text{total}}(X)$ over all $2^{w_X}$ inputs anyway.

### The non-monotonicity issue

This is the price of faithful rounding, and it is set up in [[4.1) Fixed-Point Function Approximation]]: asking only for $|R-f|<2^{\ell_R}$ leaves two legal outputs at most points, so a monotonic $f$ can be implemented by a non-monotonic $R$. The excursions are never more than one ulp, and it afflicts *every* faithful scheme — but multipartite triggers it unusually often, because the error is deliberately balanced to $\pm\delta_i$ at $x_{rl}$, exactly where two neighbouring segments meet with a slope discontinuity.

Iordache and Matula reverse-engineered AMD's K6-2 3DNow! instructions and found bipartite tables inside: **the reciprocal was monotonic, the reciprocal square root was not**, and forcing the latter monotonic cost **7.25 KB instead of 5.5 KB** — a 32% area penalty for a property the spec did not ask for.

The general fix, if you do need monotonicity: for a monotonically increasing function with decreasing derivative, use the slope at the *right* end of the interval rather than the average of the two chords. That is a strictly worse minimax fit, so $\overline{\delta_{\text{approx}}}$ grows and $g$ must grow with it (both tables get wider). The book notes no systematic study of this exists.

### ILP-optimized architectures

Formulate the whole thing as an integer linear program: one ILP variable per table entry, and for each of the $2^{w_X}$ input values two constraints encoding faithful (or correct) rounding. The ILP size therefore scales exponentially in $w_X$, capping the approach at under 16 bits today (see [[7.2) ILP for Arithmetic Design]]).

Two things it buys. First, slightly smaller architectures for faithful rounding. Second and more important, **correctly rounded** implementations — which the analytic method cannot reach, because it must bound approximation and rounding error *separately* and thereby double-counts. A correctly rounded multipartite operator is itself another lossless table compression scheme: on 16-bit functions with all tables in LUTs, LUT count fell by a **factor 5 versus LDTC compression** (p. 522). The compressor tree grows, yet latency comes out *below* a plain table's — a more compact solution routes shorter.

### Why multipartite is close to optimal among order-one methods

Every linear scheme that addresses a TIV with $\alpha$ bits inherits the $\alpha\gtrsim w_X/2$ bound derived at the top — that is a property of Taylor's theorem, not of any architecture, and it can be computed exactly per function. Empirically the best multipartite decomposition **almost always sits at the smallest $\alpha$ that still permits faithful rounding**, and the TIV is always the dominant term in the total size. Together: multipartite is near the global optimum of its family. Even a *free, perfect multiplier* would only delete the $\mathrm{TO}_i$, which are under half the total size (p. 523). To do materially better you must change the order — order two moves the bound to $\alpha\gtrsim w_X/3$ — which is [[4.3) Polynomial Approximation]].

## Other table-and-addition methods

Both are historically important and both lose to generalised multipartite (p. 526).

### Addition-table-addition (ATA)

Wong and Goto's family allows additions *before* the lookups as well as after. With $X=A+2^{-\beta}B$ and $\alpha>\beta$, start from the same first-order Taylor expansion, then approximate the derivative by a **forward difference on the same table**:

$$Bf'(A)\approx f(A+B)-f(A)\quad\Longrightarrow\quad f(A+2^{-\beta}B)\approx f(A)+2^{-\beta}\left(f(A+B)-f(A)\right)$$

Geometrically: approximate $f$ near $A$ by a copy of its own graph shrunk by $2^\beta$. Cost is one $\alpha$-bit addition, **two lookups in the same table** (dual-port, duplicated, or sequenced — a whole latency/area spectrum), one subtraction on fewer than $\alpha$ bits, a constant shift by $\beta$ (free), and one $w_R$-bit addition.

Second order swaps the forward difference for a **central difference**, whose error is third-order:

$$Bf'(A)\approx\tfrac12\left(f(A{+}B)-f(A{-}B)\right)\ \Longrightarrow\ f(A+2^{-\beta}B)\approx f(A)+2^{-\beta-1}\left(f(A{+}B)-f(A{-}B)\right)$$

Three lookups, 7 additions. The same three lookups also support a genuine second-order Taylor form, with $f''(A)\approx\left(f(A+B)-2f(A)+f(A-B)\right)/B^2$ giving

$$f(A+2^{-\beta}B)\approx f(A)+2^{-\beta-1}\left(f(A{+}B)-f(A{-}B)\right)+2^{-2\beta-1}\left(f(A{+}B)-2f(A)+f(A{-}B)\right)$$

— but the extra lookups and operations each contribute rounding error, which **consumes the accuracy the better formula just bought**. The real STAM further splits $B=B_1+2^{\beta/2}B_2$ with two centred differences plus a correction table; for 24 bits it needs 6 tables of 12–13 input bits and 9 additions (p. 526). Symmetry applies here too.

### Partial product arrays

Hassler and Takagi: approximate $f$ by a polynomial of arbitrary degree, then write $X$ *and every coefficient* as sums of weighted bits, $X=\sum x_i2^{-i}$. Distributing all the multiplications turns the polynomial into one enormous set of weighted products of the $x_i$ — a [[2.3) Sums of Weighted Bits|bit heap]]. A second approximation discards as many of those terms as possible, and the survivors are partitioned into tables.

The implementation space is enormous, which is the appeal and the problem: it must be explored heuristically. The chosen heuristic yields architectures **less compact than the multipartite ones, and interestingly similar to them**. The diagnosis is worth remembering: flattening to partial products throws away the high-level property — *continuity* — that multipartite exploits directly.

## On FPGAs: what a table actually costs

Bit count is not cost. From [[1.3) FPGAs]] and Sect. 16.4.2 (p. 491–492):

| technology | cost of a $2^k\times n$ table | source |
| --- | --- | --- |
| ASIC standard cells | $A\propto 2^{0.65\min(k,n)}\times2^{0.19\lvert k-n\rvert}$ — **symmetric in $k$ and $n$**, because synthesis shares sub-expressions between outputs | Eq. (16.1), p. 491 |
| ASIC ROM generator | very low cost/bit (only address decoding is logic), but no logic optimisation — measured *larger* than standard cells on tabulated functions | p. 491 |
| FPGA [[1.3.1) Lookup-Tables\|LUTs]], $\lambda$-input | $2^{\max(k-\lambda,0)}\times n$ LUTs; a $2^{\lambda-1}\times n$ ROM still costs $n$ LUTs (half wasted) | p. 492 |
| FPGA [[1.3.3) Block Memory\|block RAM]] | flat cost per block, very coarse output-width quantisation; relevant from a few tens of kilobits | p. 492 |

Two consequences that decide which method wins:

**The formula overestimates.** A $2^8\times8$ table for $\sin(\pi x/2)$ synthesises in **25 LUTs on a $\lambda=6$ device, not the predicted 32** — FPGA tools inherit ASIC logic optimisation. Any table-bit count is an upper bound on real LUT cost.

**The LUT/BRAM crossover is where the method choice flips.** Below the crossover everything is LUTs and *table bits translate almost linearly into LUTs*, so the compression factor is the win: the 16-bit multipartite of p. 520, costed with the $\lambda=6$ formula, is $7+104+72+28+20=231$ LUTs against $2^{10}\times16=16\,384$ for the plain table. Above the crossover a plain table becomes a handful of BRAMs — a resource you may have spare and which costs *no* logic — and multipartite's advantage collapses into "several small tables that no longer fit BRAM granularity, plus a compressor tree in fabric". Rule of thumb: if the plain ROM fits comfortably in the BRAMs you are not otherwise using, build the plain ROM. Note also that a table below $2^\lambda$ entries is *free real estate* — shrinking $\gamma_i$ past that point saves nothing, an effect invisible in the book's bit-count cost function.

## Trade-offs

$f=\sin(\pi x/4)$ throughout, faithful rounding, symmetry exploited where applicable.

| method | $w_X=w_R=8$, table bits | $w_X=w_R=16$, table bits | adders | latency | max error | source |
| --- | --- | --- | --- | --- | --- | --- |
| plain ROM | $8\cdot2^8=2048$ | $16\cdot2^{16}=1\,048\,576$ | 0 | 1 table read | 0.5 ulp (correctly rounded) | pp. 489, 520 |
| ROM + LDTC | $224+768=992$ (×0.48) | — | 1, of $w_H$ bits, or $v{=}2$ bits into a bit heap | read + 1 add (0 if merged) | 0.5 ulp (lossless) | p. 502 |
| bipartite, $m=1$ | $288+128=416$ (×4.9) | $19\,456+4608=24\,064$ (×43.6) | 1 | read + 1 add | 0.908 / 0.915 ulp | computed here |
| multipartite, $m=3$ | — | $7104+7680=14\,784$ (×70)† | 3 (compressor tree) | read + tree + CPA | <1 ulp by construction | p. 520 |
| multipartite, $m=4$ | — | $7808$ auto / $6912$ tuned (×151) | 4 | read + tree + CPA | 0.915 / 0.939 ulp | p. 521 |
| multipartite, ILP | — | ~5× fewer LUTs than LDTC | more | *lower* than plain table | correctly rounded | p. 522 |

† that row is $\tfrac{2^{16}-1}{2^{16}}\sin(\pi x/2)$, the book's own example; the others are $\sin(\pi x/4)$. Bipartite rows are computed with the equations above and verified by exhaustive evaluation over all $2^{w_X}$ inputs.

**Pick a plain ROM** when $w_X\le8$–$10$, or whenever it fits in spare block RAM: it is correctly rounded, monotonic for free, one cycle, and no adder.
**Pick LDTC** whenever you were going to build a table anyway — it is lossless, so it costs you nothing in accuracy or in verification effort, and it is free in delay if the output already feeds a compressor tree.
**Pick bipartite/multipartite** for $w_X$ between roughly 10 and 24, where the plain table has blown past BRAM and the exponential is unbearable; take larger $m$ when LUTs are scarce and adders are not. Above 24 bits the TIV is exponential again and you must move to [[4.3) Polynomial Approximation]] — order two relaxes $\alpha\gtrsim w_X/2$ to $\alpha\gtrsim w_X/3$, which is worth a squarer or a DSP block.

## Worked example: 8-bit bipartite $\sin(\pi x/4)$

$w_X=8$, $\ell_X=\ell_R=-8$, $f(x)=\sin(\pi x/4)$ on $[0,1)$, range $[0,0.7071)$ so $m_R=-1$ and $w_R=m_R-\ell_R+1=8$.

**Parameters.** The rule of thumb gives $\alpha\approx16/3\approx5.3$, $\beta\approx\gamma\approx2.7$; the search settles on $\alpha=5$, $\beta=3$, $\gamma=3$, $m=1$.

$$X=\underbrace{x_1x_2x_3}_{C}\underbrace{x_4x_5}_{\text{rest of }A}\underbrace{x_6x_7x_8}_{B}\qquad \Delta_0=2^{-8}(2^3-1)=\tfrac{7}{256}$$

**Slopes and approximation error,** from the balanced-error equations, $C=0\ldots7$:

| $C$ | 0 | 1 | 2 | 3 | 4 | 5 | 6 | 7 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- |
| $s(C)$ | 0.78396 | 0.77653 | 0.76162 | 0.73938 | 0.71001 | 0.67381 | 0.63111 | 0.58234 |
| $\delta(C)$ (ulp) | −0.0048 | −0.0147 | −0.0244 | −0.0339 | −0.0431 | −0.0519 | −0.0602 | −0.0678 |

$|\delta(C)|$ grows monotonically with $C$, as convexity predicts, so $\overline{\delta_{\text{approx}}}=|\delta(7)|=0.0678$ ulp $<0.5$ ulp — accepted.

**Guard bits.** $g=\left\lceil-9+\log_2 1-\log_2\!\left(2^{-9}-0.0678\cdot2^{-8}\right)\right\rceil=\lceil0.21\rceil=\mathbf{1}$. Tables are filled at $\ell_R-g=-9$.

**TIV**, $2^5=32$ entries of $w_R+g=9$ bits, $\mathrm{TIV}(A)=\left\lfloor 2^{9}\cdot\frac{f(A/32)+f(A/32+7/256)}{2}+\tfrac12\right\rfloor$:

$$\mathrm{TIV}[0..7]=5,\,18,\,31,\,43,\,56,\,68,\,81,\,93,\ \dots,\ \mathrm{TIV}[31]=357=\mathtt{101100101}_2$$

357 needs exactly 9 bits ✓.

**TO**, addressed by $C\Vert B$ — $2^{\gamma+\beta}=64$ conceptual entries, halved to 32 by symmetry. Width: $r_0=\max|s(C)\Delta_0|=0.02144$, $m_0=\lceil\log_2 r_0\rceil=-5$, so $m_0-\ell_R+g=\mathbf{4}$ bits signed. In units of $2^{-9}$:

$$\mathrm{TO}[C{=}0,\,B{=}0..7]=-5,\,-4,\,-2,\,-1,\;\mathbf{1},\,\mathbf{2},\,\mathbf{4},\,\mathbf{5} \qquad \mathrm{TO}[C{=}7]=-4,\,-3,\,-2,\,-1,\;\mathbf{1},\,\mathbf{2},\,\mathbf{3},\,\mathbf{4}$$

Only the bold half is stored; $b_6$ (the MSB of $B$) selects, and the XOR row complements the rest.

**Size.** $32\times9+32\times4=288+128=\mathbf{416}$ bits against $2^8\times8=2048$ — a factor **4.9**, one 9-bit adder, one XOR row.

**Trace $X=\mathtt{00101101}$** ($=45/256=0.17578$):

$$A=\mathtt{00101}=5,\quad B=\mathtt{101}=5,\quad C=\mathtt{001}=1$$
$$\mathrm{TIV}[5]=68=\mathtt{001000100},\qquad \mathrm{TO}[1,5]=+2=\mathtt{0010}$$
$$S=68+2=70=\mathtt{001000110}\ \text{(at }2^{-9}),\qquad R=\text{trunc}\to\mathtt{00100011}=35$$

Exact: $2^8\sin(\pi\cdot45/1024)=35.2308$. **Error $=-0.231$ ulp.**

**Worst case, exhaustive over all 256 inputs:** $X=\mathtt{00100000}$, $A=\mathtt{00100}$, $B=\mathtt{000}$, $C=\mathtt{001}$, $\mathrm{TIV}[4]=56$, $\mathrm{TO}[1,0]=-5$, $S=51$, $R=\mathtt{00011010}=26$ against $25.0924$ exact.

$$\boxed{\max_X|\delta_{\text{total}}|=0.9076\ \text{ulp}<1\ \text{ulp}}$$

Faithful, and the excursion sits at $B=0$ — the segment boundary, exactly where the balanced-error construction puts it. This instance happens to be **monotonic** over all 256 inputs; the 16-bit case ($\alpha=10$, $\beta=6$, $\gamma=4$, $g=3$, 24 064 bits, 0.915 ulp) is too. Monotonicity is not guaranteed by the method — it has to be checked, and here it was.
