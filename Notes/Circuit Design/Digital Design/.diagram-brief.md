# Agent brief — adding diagrams to an existing note

Your assignment names one note in `Notes/Digital Design/`. It is already written
and technically sound. **Do not rewrite it.** Your only job is to add diagrams
where they carry real explanatory load, because the note currently runs several
hundred lines on one figure.

## Block format — exact, non-negotiable

These notes render in two places: Obsidian's TikZJax plugin, and the static site
(`build/markdown/generate-latex-diagrams.ts`). One format satisfies both:

````
```tikz title="Short caption for alt text"
\usepackage{circuitikz}
\begin{document}
\begin{circuitikz}
  ... drawing commands ...
\end{circuitikz}
\end{document}
```
````

- Fence language is `tikz` — Obsidian's TikZJax only registers a processor for
  that language, so a ```` ```circuitikz ```` fence renders as a plain code block
  in the vault. The site generator sniffs the *environment*, not the fence.
- Environment is `circuitikz`, never `tikzpicture`. circuitikz is a superset, so
  ordinary `\node`/`\draw` work, and it additionally gives you real gate and
  flip-flop shapes.
- Any `\usetikzlibrary{...}` goes between `\usepackage` and `\begin{document}`.
  **`arrows.meta` is not bundled by TikZJax** — use `arrows` and the classic
  `latex` / `stealth` tips instead of `{Latex}` / `{Stealth}`.
- No `\documentclass` — both renderers supply it.

## What to add

Add **2–3 diagrams**. Read the note first and place them where a reader is
currently asked to hold a structure in their head from prose alone. Good
candidates, in rough priority order:

1. **The datapath or block structure** being derived, if the note has none.
2. **A dot diagram / bit-position picture** wherever the note manipulates bit
   heaps, partial products, arrays, or table splits — these are almost always
   clearer as a picture than as prose.
3. **The worked example, drawn.** If the note walks concrete operands through
   stages, a figure showing the values at each stage is worth more than the
   table it currently has.
4. **A comparison figure** placing two variants side by side, when the note's
   trade-off table compares structures rather than just numbers.

Label **every signal with its bit width**. Caption each diagram with the book
figure it derives from where one exists (*after Fig. 8.12, p. 227*); say nothing
if it is your own construction.

For gate-level notes use circuitikz's own shapes — `\node[and port]`,
`\node[nor port]`, `\node[xor port]`, `\node[flipflop D]` — rather than boxes
with text. For datapath and architecture diagrams, labelled rectangles are
correct and preferred; do not force circuit symbols where blocks are the honest
representation.

## Verify before you finish

Compile them. From the repository root:

    nix develop path:. --command bun run build/markdown/generate-latex-diagrams.ts

It prints `Prepared N LaTeX diagrams (M compiled)` and lists any failure with its
`file:line`. Your diagrams must compile. Then rasterize at least one and look at
it, so you catch overlapping labels that LaTeX compiles happily:

    magick -density 130 -background white site/public/assets/diagrams/<hash>.svg /tmp/check.png

Fix collisions and re-verify. A diagram that compiles but is unreadable is worse
than no diagram.

Keep to base PGF plus circuitikz. `pgfmath` overflows above 16384, so never form
a squared quantity that large — use `veclen(a,b)` instead of `sqrt(a*a+b*b)`.

## Prose

Touch the surrounding prose only to introduce a figure where the flow needs it —
one sentence, at most. Do not restructure sections, do not add or remove claims,
do not change any number.

## Report back

File, how many diagrams you added and where, confirmation that they compile,
which ones you rasterized and checked, and anything you wanted to draw but
could not.
