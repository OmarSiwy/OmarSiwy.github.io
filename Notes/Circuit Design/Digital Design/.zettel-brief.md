## Structure

One `##` heading in the whole note — `## References`. Everything else flows in
the body under the H1. This matches the Analog Design notes; do not introduce a
second sectioning convention.

**1. One-line summary.** Exactly one sentence, stating what the circuit is and
the one property that distinguishes it from its siblings.

**2. Diagram.** A fenced ` ```tikz ` block, then an italic caption naming the
figure it derives from: *after Fig. 5.15, p. 121*. Say nothing if it is your own
construction. Format and verification are below.

**3. Topic.** Multiple paragraphs. Every paragraph opens with a **bold subgoal
lead** naming what that paragraph accomplishes — "**Turn the carry into a
recurrence.**" — not a restatement of the heading. KaTeX inline `$...$` and
display `$$...$$`. **Name the law at every rewriting step**: "by distributivity
of AND over OR", "two's-complement identity $-x = \bar{x} + 1$", "associativity
lets us reassociate the carry chain into a prefix tree". A reader reproduces
every line without the book open.

State **every signal's bit width**. Ground format and error reasoning in
[[Number Formats]] and [[Error Accuracy]] by linking, never by re-deriving ulp,
rounding modes, or two's-complement basics.

Where FPGA mapping differs from ASIC, say so inline — this reader targets both,
and the book is unusually good on the FPGA side.

**4. Result.** The boxed identity, recurrence, or cost expression the note
establishes:

```md
$$\boxed{\ c_{i+1} = g_i \vee (p_i \wedge c_i)\ }$$
```

**5. When it breaks.** A short list: corner cases, the width at which the
asymptotics stop mattering, the assumption that fails, where a sibling takes
over.

**6. RTL (Spade).** See below.

**7. Related Notes (with context).** Each link carries a typed relation and a
clause of context — never a bare link:

```md
- [[Choosing an Adder]] – compares: where this sits against every sibling.
- [[Kogge-Stone Tree]] – extends: reassociates this chain into a tree.
- [[FPGA Hard Carry Chain Adder]] – counter-example: asymptotics reverse once
  the chain is hardened into silicon.
```

Those are real note names. **Use the names your assignment gives you** — they
already exist as files. Inventing a plausible variant (`Kogge-Stone Adder` for
`Kogge-Stone Tree`) is the single most common way to create a dead link.

Use `extends` / `supports` / `compares` / `counter-example` / `depends-on`.
Link to the note names in your assignment. Linking to a note that does not exist
yet is expected and fine — but prefer the names in your assignment over invented
ones, because those files already exist as stubs.

**8. `## References`.** The sections and printed page numbers you actually used.

## The Spade block

Spade is an HDL, Rust-inspired. Read `/tmp/spade_ref/SPADE-CHEATSHEET.md`
before writing a line of it. Every snippet in that sheet was compiled, not
invented.

**Check your block before you ship it:**

```sh
/tmp/spade-src/target/release/spade FILE.spade -o /dev/null --no-color
```

Exit 0 is clean. Stdlib is embedded, no flags needed; `-o` is mandatory because
there is no `--check` mode. Iterate until it passes. **A failing block blocks the
note** — never ship RTL you have not compiled.

> **A generic entity is only type-checked at monomorphisation.** A generic
> `entity rca<#uint W>(...)` with a width bug in its body compiles clean until a
> concrete call site exists. Append a concrete instantiation to the file you
> compile — `fn t() -> (uint<9>) { inst rca::<8>(...) }` — or "verified" means
> nothing. The instantiation stays in the temp file; only the entity goes in the
> note.

Follow the block with 2-4 lines tying the RTL back to the diagram: which signal
is which wire, the width arithmetic, combinational versus registered, and the
one thing synthesis will do differently from the drawing.

The three traps that bite arithmetic code:

| trap | reality |
|---|---|
| width growth | `+`,`-` → `N+1`; `*` → `2N`; `/`,`%`,shifts → `N`. Truncating variants are `+.` `-.` `*.` `<<.` `>>.` |
| `as` | type *ascription*, not a cast. Convert with `as_int` / `as_uint` / `zext` / `sext` / `trunc` |
| bit access | integers are not indexable — go via `.as_bits()`, index 0 = LSB |

Also: `^` is **not** XOR on `bool` (use `!=`); `!` is bool-only, `~` is bitwise;
there is no `let mut`, no `return`, no Verilog `{a,b}` concatenation.

### When `spade: not-expressible`

Only for circuits needing combinational feedback. Spade has no latch primitive
and `let` cannot self-reference. Quote the **real** compiler error — run it,
do not paraphrase:

```spade
let q = if en { d } else { q };   // error: Use of undeclared name q
```

Then show the nearest structure Spade is native at, compiled, and say what it
does and does not capture. **Do not pass the feedback in as an argument to make
it compile** — it type-checks and it is a mux, not a latch.

### When `spade: n/a`

No RTL block. One line saying why nothing is synthesizable.

### If your circuit is `iterative`

SRT division, Goldschmidt, CORDIC, digit recurrences: show **one iteration** of
the recurrence as an `entity`, plus a line on how many iterations the operator
needs and what the loop control costs. Do not attempt a 24-iteration unrolled
entity.

## The diagram

Exact format, non-negotiable — it must satisfy both Obsidian's TikZJax and the
site's `build/markdown/generate-latex-diagrams.ts`:

````
```tikz title="Short caption, used as alt text"
\usepackage{circuitikz}
\begin{document}
\begin{circuitikz}
  ... drawing commands ...
\end{circuitikz}
\end{document}
```
````

- Fence language is `tikz`. TikZJax registers a processor only for that word, so
  a ```` ```circuitikz ```` fence renders as a plain code block in the vault.
- Environment is `circuitikz`, never `tikzpicture`. circuitikz is a superset, so
  plain `\node`/`\draw` work and you additionally get gate and flip-flop shapes.
- No `\documentclass` — both renderers supply it.
- `\usetikzlibrary{...}` goes between `\usepackage` and `\begin{document}`.

**Label every signal with its bit width.** For gate-level circuits use
circuitikz's own shapes — `\node[and port]`, `\node[xor port]`,
`\node[flipflop D]`. For datapath and architecture diagrams labelled rectangles
are the honest representation; do not force circuit symbols onto blocks.

**Verify it, then look at it:**

```sh
nix develop path:. --command bun build/markdown/preview-diagram.mjs block.tikz out.png
```

from the repository root, where `block.tikz` holds exactly what goes inside the
fence. Then `Read` the PNG. A diagram that compiles with overlapping labels is
still broken — fix collisions and re-render.

### Vocabulary that is known to render

The dev shell has TeX Live 2025; Obsidian's TikZJax bundles circuitikz up to
0.9.6. **A local compile catches syntax and layout errors, never version
drift**, so stay inside what is already proven in this vault:

- `nmos`/`pmos` with `.gate`/`.drain`/`.source` anchors · `node[ground]`,
  `[vcc]`, `[ocirc]`, `[circ]` · `xscale=-1` mirroring ·
  `to[R/C/L/I/V/short/open/switch]` · `-|` and `|-` wiring · `$( ... )$` calc ·
  `\foreach` · `\begin{scope}[xshift=]` · `node[op amp]` · `pgfplots` ·
  plain `tikz` block diagrams and waveforms.
- **`arrows.meta` is not bundled** — use `arrows` with the classic `latex` /
  `stealth` tips, never `{Latex}` / `{Stealth}`.
- **`right=2pt of X` needs `\usetikzlibrary{positioning}`**, which is not loaded
  by default. Prefer plain coordinates: `\node[anchor=west] at (0.55,0.3) {...};`
- `pgfmath` overflows above 16384 — use `veclen(a,b)`, never `sqrt(a*a+b*b)`.

If a book figure genuinely cannot be redrawn faithfully — dense FPGA tiling
maps, multi-panel plots — crop it instead, headless:

```sh
pdftotext -f <pdfpage> -l <pdfpage> -bbox Dienchin.pdf - | grep -i 'Fig\.'
pdftoppm -f <pdfpage> -l <pdfpage> -r 150 -png -x <X> -y <Y> -W <W> -H <H> \
  Dienchin.pdf assets/<slug>
```

`Read` the PNG to confirm the framing. Write to `assets/`, reference as
`![alt](assets/name-01.png)` — markdown image syntax only, never Obsidian
`![[embed]]`. Prefer redrawing. Report every crop.

## Style

- No filler, no "in conclusion", no restating the title in the first sentence.
- Cut any section with nothing real to say rather than padding it.
- `> [!note]` and `> [!important]` callouts are reserved for the single idea that
  matters most in the note. One per note at most, usually zero.
- Explain *why* a circuit is built the way it is, not merely what it does.
