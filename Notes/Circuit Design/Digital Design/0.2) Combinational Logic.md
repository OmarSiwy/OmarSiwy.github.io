**Specification.** Input: an $n$-bit vector $x\in\{0,1\}^n$. Output: an $m$-bit vector $y\in\{0,1\}^m$. Accuracy: **exact, $0$ ulp** — a combinational block realises a truth table, and every entry is met bit-for-bit; approximation error only enters when you deliberately shrink the table ([[1.2) Error Accuracy]]). What is optimised: **latency** (worst-case propagation delay through the block), subject to an area budget, with switching energy as a third axis once glitches enter the picture.

Everything below traces back to that: the block is exact by construction, so the only design freedom is *how the same table is factored*, and factoring trades depth against gate count against glitch energy.

## The combinational contract

A block is combinational when its output is a **pure function of the present input**. Three conditions, and they are not the same statement:

1. **No state.** $y = f(x)$, with no dependence on input history. No latch, no memory element, no feedback.
2. **Totally defined.** $f$ is defined for all $2^n$ input patterns. "Don't cares" are a *synthesis* freedom, not a runtime freedom — the built circuit produces *some* definite value there, and you do not get to be surprised by which.
3. **Settling.** After the last input transition, the output reaches $f(x)$ and stays there, within a bounded time $t_{pd}$. Before that it may be anything at all.

Point 3 is the one people forget. The contract says nothing about the *interval* between the input change and $t_{pd}$; the output is free to wiggle, and it does (see [Glitches and hazards](#glitches-and-hazards)). Combinational logic is a promise about a **final value**, never about a waveform.

Structurally the sufficient condition is that the gate graph is a **DAG**: no directed cycle from any output back to any input. Acyclic implies combinational. The converse is false — cyclic combinational circuits exist and are occasionally smaller — but no mainstream synthesis tool will produce one and no static timing analyser can time one, so treat acyclicity as the rule.

> [!important] This contract is what makes static timing analysis possible
> Because the output depends only on the present input, timing closure decomposes: you time each combinational cloud *between registers* independently, and the sequential elements ([[0.3) Introduction to Flip-Flops & Latches]]) stitch the results together with one setup and one hold inequality. Break the contract — add feedback, add a latch you did not mean to infer — and there is no longer a finite path to enumerate.

## Standard blocks

Everything in this table is a truth table; the reason to name them is that synthesis, FPGA architecture and your own factoring all recognise these shapes.

| Block | Function | Gate-level cost (2-input gates) | Depth |
| --- | --- | --- | --- |
| Decoder $n\!\to\!2^n$ | $Y_i = \prod_j x_j^{(i_j)}$, one-hot | $2^n$ AND$n$ + $n$ INV | $1$ AND$n$ level, $\lceil\log_2 n\rceil$ if tree-built |
| Demux $1\!\to\!2^n$ | $Y_i = D\cdot(x=i)$ | decoder + $2^n$ AND2 | decoder $+1$ |
| Encoder $2^n\!\to\!n$ | inverse of decoder, **valid only on one-hot input** | $n$ OR$(2^{n-1})$ | $\lceil\log_2 2^{n-1}\rceil$ |
| Priority encoder | index of the highest set bit | prefix-OR + encoder | $\lceil\log_2 2^n\rceil$ |
| Mux $2^n\!\to\!1$ | $Y=\sum_i S_i^{\text{dec}} D_i$ | $2^n-1$ MUX2, or decoder + AND-OR | $n$ MUX2 levels |
| Equality comparator | $A=B$ | $n$ XOR2 + NOR$n$ | $1+\lceil\log_2 n\rceil$ |
| Parity | $\bigoplus_i x_i$ | $n-1$ XOR2 | $\lceil\log_2 n\rceil$ |

**Decoders.** The flat form is $2^n$ AND gates of $n$ inputs each — $n2^n$ gate inputs, and an $n$-input AND has terrible logical effort past $n=4$ ([Fan-in, fan-out and logical effort](#fan-in-fan-out-and-logical-effort)). The fix is **predecoding**: split $x$ into two halves, build two $\tfrac n2$-decoders producing $2^{n/2}$ partial minterms each, then AND pairs. Cost drops from $n2^n$ to $2\cdot 2^{n+1}$-ish gate inputs and every gate becomes an AND2. This is exactly the factoring an SRAM row decoder uses.

**Encoders and priority encoders.** A plain encoder is a wire-OR and is only correct if the input really is one-hot; feed it two hot bits and it silently emits the OR of two addresses, which is a legal address for neither. A **priority encoder** removes the precondition by defining the output as the index of the *highest* set bit. Naively that is a ripple: bit $k$ outputs iff no higher bit is set, a chain of length $2^n$. Write it instead as

$$h_k = \bigvee_{j>k} x_j, \qquad s_k = x_k \cdot \overline{h_k}$$

$h$ is a **prefix-OR** scanned downward. OR is associative, so — by exactly the reassociation argument that turns a ripple carry into a prefix tree in [[2.1.5) Parallel Prefix Adders]] — the chain becomes a $\lceil\log_2 2^n\rceil$-deep tree. $s$ is then one-hot and a plain encoder finishes the job. The same construction is a [[2.6.2) Leading Zero Counters]] with the output relabelled.

**Multiplexers.** Two constructions. The **one-hot** form decodes the select and drives a wide AND-OR: one gate level after the decoder, but the OR is $2^n$-wide. The **tree** form is $2^n-1$ MUX2s in $n$ levels: no wide gate anywhere, and it is the form that generalises (next section). In CMOS a MUX2 is often built from two transmission gates plus one inverter — 6 transistors versus ~12 static — but series transmission gates form an RC ladder whose delay grows quadratically, so buffer every two or three levels.

**Comparators.** Equality is an XOR tree fed to a NOR: $A=B \iff \bigvee_i (a_i\oplus b_i) = 0$. Magnitude comparison is *not* a tree of local decisions — it is a prefix problem, structurally the carry-out of $A-B$, and belongs with [[2.2) Comparators]].

**Parity / XOR trees.** $\oplus$ is associative and commutative, so the linear chain of depth $n-1$ reassociates freely into a balanced tree of depth $\lceil\log_2 n\rceil$. The gate count stays $n-1$ either way — reassociation buys depth for free, which is the single most reused trick in this whole vault. The catch is that XOR is the most expensive static gate there is ($g=4$, $p=4$), so an XOR tree is dominated by its *gates*, not its depth.

## Shannon expansion: every function is a mux tree

Start from the identity that generates all of this. For any $f$ and any variable $x$:

$$f = 1\cdot f = (x+\bar x)\,f = x f + \bar x f$$

by the **complement law** $x+\bar x=1$ and **distributivity of AND over OR** ([[0.1) Boolean Algebra]]). Inside the term $xf$, the literal $x$ is $1$, so by **idempotence** $x\cdot x=x$ and **complementation** $x\cdot\bar x=0$ every occurrence of $x$ in $f$ collapses to a constant, giving $xf = x\,f|_{x=1}$; dually $\bar x f = \bar x\, f|_{x=0}$. Hence the **Shannon expansion**

$$\boxed{\;f(x_{n-1},\dots,x_0) = \bar x_{k}\, f_{\bar x_k} + x_{k}\, f_{x_k}\;}$$

where $f_{x_k}=f|_{x_k=1}$ and $f_{\bar x_k}=f|_{x_k=0}$ are the **cofactors**. Read the right-hand side as hardware and it *is* a 2:1 mux: select $x_k$, data inputs the two cofactors.

Recurse on every remaining variable. Each level halves the number of free variables and doubles the number of cofactors; after $n$ levels the cofactors are constants — the $2^n$ rows of the truth table. What is left is:

- a binary tree of $2^n-1$ MUX2s, depth $n$,
- whose $2^n$ leaves are the truth-table bits,
- addressed by $x$ as a word line.

That object is a $2^n\times 1$ ROM. It is also, exactly and not by analogy, **an $n$-input lookup table**.

> [!important] This is what an FPGA LUT is
> A Xilinx/AMD LUT6 is 64 SRAM configuration cells feeding a 63-node binary tree of pass transistors steered by the six inputs. That tree is the fully-recursed Shannon expansion of an arbitrary 6-variable function, executed in silicon, with the cofactor leaves made writable. **"Programmable logic" means programmable truth table, and the mux tree is the evaluator.** The consequences run all the way through [[1.3) FPGAs]] and [[1.3.1) Lookup-Tables]].

Stopping the recursion early is equally useful: expand on one variable and you have split $f$ into two smaller problems plus a mux — the basis of **functional decomposition** and of LUT technology mapping. It is also why FPGA fabrics ship dedicated `MUXF7`/`MUXF8` cells next to the LUTs: they perform one and two *further* Shannon steps above the LUT6 boundary, combining two LUT6s into a 7-input function and four into an 8-input one, without paying general routing.

## Propagation delay, contamination delay, and the critical path

Two delays per block, and they are not the same number:

- $t_{pd}$ — **propagation delay**, the *maximum* over all inputs and all transitions from the last input change to the output being stable and correct. An upper bound.
- $t_{cd}$ — **contamination delay**, the *minimum* over all inputs and transitions from an input change to the output *starting* to change. A lower bound.

$t_{cd}\le t_{pd}$ always, and in a real block they can differ by an order of magnitude, because $t_{pd}$ follows the longest sensitised path and $t_{cd}$ the shortest.

The **critical path** is the input-to-output path maximising $t_{pd}$. Note what it is not: it is not the longest path in the graph, because some long paths are *false* — not sensitisable by any input vector — and a timing tool that ignores false paths reports a pessimistic critical path. It is also not stable across the design; fix the critical path and a different one takes over, which is why speeding a design up shows diminishing returns almost immediately.

Both numbers are consumed by the sequential timing constraints of [[0.4) Synchronous Sequential Logic]]: $t_{pd}$ bounds the clock period through setup, and $t_{cd}$ must be *large enough* to satisfy hold. A block that is too fast is a hold violation, and hold violations do not go away by slowing the clock.

## Glitches and hazards

A **hazard** is the possibility of a transient output value that the truth table does not contain. Three shapes, all for a **single** input changing:

| Hazard | Output should | Output actually does | Where it lives |
| --- | --- | --- | --- |
| Static-1 | stay $1$ | $1\to0\to1$ | two-level SOP (AND-OR) |
| Static-0 | stay $0$ | $0\to1\to0$ | two-level POS (OR-AND) |
| Dynamic | go $0\to1$ (or $1\to0$) once | $0\to1\to0\to1$ | $\ge3$ levels with reconvergent fanout |

**Static-1, and how consensus kills it.** Take the 2:1 mux itself, $Y=\bar S A + S B$. Hold $A=B=1$ and toggle $S$. The truth table says $Y=1$ throughout. The circuit says: the $\bar S A$ product turns off as soon as $S$ rises, and the $SB$ product turns on only after $S$ propagates — if the inverter on $S$ is slow the two products are momentarily both $0$ and $Y$ dips. On the K-map the two ON-cells $(S{=}0,A{=}1,B{=}1)$ and $(S{=}1,A{=}1,B{=}1)$ are adjacent but covered by **different** products, and that is the whole diagnosis:

> A two-level SOP is free of static-1 hazards **iff every pair of adjacent ON-set cells is covered by some single product term.**

The repair is to add the missing cover, and the missing cover is precisely the **consensus term** of the two products with respect to $S$ — by the consensus theorem $XY + \bar X Z + YZ = XY + \bar X Z$ ([[0.1) Boolean Algebra]]), the term $AB$ is logically redundant and can be added for free:

$$Y = \bar S A + S B + \underbrace{AB}_{\text{consensus}}$$

Now while $S$ is in flight the $AB$ product holds the output up. The redundancy is the point: **you are paying area to buy a timing property**, which is why logic optimisers strip these terms out again unless you tell them not to.

*All nets 1 bit. Drawn on the $S{:}1\to0$ edge, the one where the surviving product has to wait for the inverter; the rising edge is the mirror image. My own construction.*

Static-0 is the exact dual: work in POS, adjacency of OFF-set cells, add the consensus *sum* term. For the mux, $Y=(S+B)(\bar S+A)$ glitches high at $A=B=0$, fixed by appending $(A+B)$.

**Dynamic hazards** cannot be fixed this way. They need three or more levels plus reconvergent fanout with unequal delays, and no amount of adding redundant terms to one level removes them; you either flatten to a hazard-free two-level form, balance the path delays, or accept the glitch.

> [!warning] Function hazards are a different animal and cannot be removed at all
> Everything above assumes **one** input changes. When two or more change "simultaneously" — and simultaneity does not exist in hardware — the circuit traverses some intermediate vertex of the Boolean cube, and if $f$ differs at that vertex, the output *must* glitch. That is a **function hazard**: a property of $f$, not of the implementation. No factoring, no consensus term, no delay balancing removes it. The three hazards in the table are **logic hazards**, artefacts of the gate netlist, and those are the removable ones.

Practically: inside a synchronous pipeline you ignore all of it — the register samples after $t_{pd}$ and glitches are invisible to function. They are *not* invisible to **power**: an ASIC adder can burn 20-40% of its switching energy on glitches, and on an FPGA a deep LUT cascade glitches on every level. Hazard-freedom becomes mandatory only when the signal feeds something level-sensitive: a clock, an asynchronous reset, a latch enable, or the next-state logic of [[0.5) Asynchronous Sequential Logic]].

## Fan-in, fan-out and logical effort

The unit-gate model — "count levels" — is wrong in a specific and predictable way: it prices a NAND4 the same as a NAND2. **Logical effort** fixes that with a one-line delay model, in units of $\tau$ (the delay of an inverter driving an identical inverter with no parasitics):

$$d = f + p = g\,h + p,\qquad h=\frac{C_{\text{out}}}{C_{\text{in}}}$$

$g$ (**logical effort**) is how much worse the gate is than an inverter at driving current, per unit of input capacitance. $h$ (**electrical effort**, the fan-out) is the load ratio. $p$ (**parasitic delay**) is the self-loading, independent of load.

| Gate | $g$ | $p$ |
| --- | --- | --- |
| INV | $1$ | $1$ |
| NAND2 / NAND3 / NAND$n$ | $\tfrac43$ / $\tfrac53$ / $\tfrac{n+2}{3}$ | $2$ / $3$ / $n$ |
| NOR2 / NOR3 / NOR$n$ | $\tfrac53$ / $\tfrac73$ / $\tfrac{2n+1}{3}$ | $2$ / $3$ / $n$ |
| XOR2 | $4$ | $4$ |
| MUX2 (per data or select input) | $2$ | $4$ |

Read the fan-in penalty straight off the table: $g$ grows *linearly* in $n$ and $p$ grows linearly in $n$ too, so a wide gate is hit twice. Past $n\approx4$ it is always faster to build a tree of narrow gates, even though the tree is deeper. That is the quantitative reason decoders are predecoded and wide ORs are treed.

For a path of $N$ stages the model composes multiplicatively:

$$F = GBH,\qquad G=\prod g_i,\quad B=\prod b_i,\quad H=\frac{C_{\text{end}}}{C_{\text{start}}}$$

with $b_i$ the **branching effort** at stage $i$ (total load / on-path load). Minimising $D=\sum(g_ih_i+p_i)$ subject to fixed $F$ gives equal stage effort $\hat f = F^{1/N}$, so

$$\boxed{\;D_{\min} = N F^{1/N} + P\;},\qquad P=\sum p_i$$

Differentiating with respect to $N$ puts the optimum at $\hat f \approx 3.6$, universally rounded to $4$ — the origin of the **FO4** delay as the technology-independent yardstick.

## Worked example: a 4:1 multiplexer, two ways

$w=1$, unit input capacitance, unit output load ($H=1$).

**Design A — tree of three MUX2s.** Netlist: 3 muxes ($2\times$AND2 $+$ OR2 each) $=9$ gates, 18 gate-inputs, plus 2 shared select inverters $=$ **11 gates, 20 gate-inputs**.

*Data path* $D_i \to$ MUX2 $\to$ MUX2 $\to Y$, $N=2$:

$$G = 2\cdot 2 = 4,\quad B=1,\quad H=1 \;\Rightarrow\; F=4,\quad \hat f=\sqrt4=2$$
$$P = 4+4 = 8 \;\Rightarrow\; D = 2(2)+8 = \mathbf{12\,\tau}$$

*Select path*, worst case $S_0$ (drives both level-1 muxes, so $B=2$), $N=2$ through its inverter:

$$F = (1)(2)(2)(1) = 4,\quad \hat f = 2,\quad P = 1+4 = 5 \;\Rightarrow\; D = 2(2)+5 = 9\,\tau$$

Critical path: **the data path, $12\,\tau$**, 4 gate levels.

**Design B — flat two-level AND-OR.** $Y=D_0\bar S_1\bar S_0 + D_1\bar S_1 S_0 + D_2 S_1\bar S_0 + D_3 S_1 S_0$, built NAND-NAND: 4 NAND3 $+$ 1 NAND4 $+$ 2 INV $=$ **7 gates, 18 gate-inputs**.

*Data path* $D_i\to$ NAND3 $\to$ NAND4 $\to Y$, $N=2$:

$$G=\tfrac53\cdot 2=\tfrac{10}{3},\quad B=1,\quad F=3.33,\quad \hat f = \sqrt{3.33}=1.83$$
$$P = 3+4 = 7 \;\Rightarrow\; D = 2(1.83)+7 = 10.7\,\tau$$

*Select path* $S_0\to$ INV $\to$ NAND3 $\to$ NAND4, $N=3$; the inverter output feeds two NAND3s so $B=2$:

$$F = \left(1\cdot\tfrac53\cdot 2\right)(2)(1) = 6.67,\quad \hat f = 6.67^{1/3}=1.88$$
$$P = 1+3+4 = 8 \;\Rightarrow\; D = 3(1.88)+8 = \mathbf{13.6\,\tau}$$

**Result.** The unit-gate model says B wins easily — 3 levels against 5. Logical effort says the opposite: **B is $13.6\,\tau$ against A's $12\,\tau$**, because B's advantage in depth is more than spent on a 4-input NAND ($p=4$) and on decoding the select through a branch of 2. The flat implementation is shallower and slower. This inversion is the entire argument for not trusting level counts.

## FPGA mapping

On an FPGA the whole comparison above evaporates below the LUT boundary. A 4:1 mux has $4+2=6$ inputs, so it fits **one LUT6 exactly**: $1$ LUT, depth $1$, one routing hop. Design A and Design B are the same circuit after technology mapping, and arguing about NAND4s is arguing about a netlist the mapper deleted.

What survives:

- **Count inputs, not gates.** The unit of FPGA area is "a function of $\le6$ variables". Any cone of logic with 6 or fewer inputs is free relative to one with 7. Restructuring to reduce the *support* of each node is the whole game of LUT mapping.
- **Above 6 inputs, Shannon again.** An 8:1 mux is 11 inputs: two LUT6s plus a `MUXF7`, i.e. one more Shannon step in dedicated silicon. A 16:1 mux is four LUT6s $+$ 2 `MUXF7` $+$ 1 `MUXF8`.
- **Fracturable LUTs.** A LUT6 splits into two LUT5s *sharing* their five inputs — a Shannon expansion left one level short, with the top mux exposed. Two functions of the same 5 variables cost one LUT.
- **XOR is free.** A 6-input parity costs one LUT, so a 64-bit parity tree is $\lceil\log_6 64\rceil = 3$ LUT levels rather than 6 XOR levels. On an ASIC the XOR tree is gate-dominated ($g=4$); on an FPGA it is input-count-dominated. Opposite optimisations.
- **Glitches cost real power.** LUT outputs glitch freely and the fabric's routing capacitance is large, so a deep unpipelined LUT cascade burns disproportionate dynamic power. The FPGA answer is not consensus terms — it is a register, which the fabric gives you for free next to every LUT.

## Trade-offs

Costs derived by construction for a $w=1$, 4:1 multiplexer; $\tau$ values from the logical-effort model above with $H=1$.

| | Mux tree (A) | Two-level AND-OR (B) | LUT6 (C) |
| --- | --- | --- | --- |
| Gates | 11 | 7 | 1 LUT |
| Gate inputs (area proxy) | 20 | 18 | fixed, 64 SRAM cells |
| Static CMOS transistors | 40 (16 with TG muxes) | 36 | fixed |
| Logic depth (levels) | 5 | 3 | 1 |
| Critical path | $12\,\tau$ (data) | $13.6\,\tau$ (select) | 1 LUT $+$ 1 hop |
| Widest gate | 2 inputs | 4 inputs | — |
| Scaling to $2^n\!:\!1$ | $2^n-1$ muxes, depth $n$ | $2^n$ AND$(n{+}1)$ + OR$2^n$, depth 2 but unbuildably wide | $\lceil n/5\rceil$-ish LUT levels |
| Glitches | 1 per level per select change; consensus term $D_{2i}D_{2i+1}$ per mux | static-1 on every adjacent select pair; 4 consensus products | not hazard-free; internal tree skew |
| Hazard-free variant cost | $+3$ AND2, ORs widened to 3 | $+4$ AND2, OR widened to 8 | not expressible — you do not control the tree |

Pick the **mux tree** whenever the select count grows: nothing ever exceeds 2 inputs, depth grows as $\log$, and it is the only form that scales past $n=3$ without an unbuildable gate. Pick **two-level AND-OR** only for genuinely small, genuinely flat functions, or when you need a provably hazard-free result — two-level is the only form where hazard-freedom has a clean K-map criterion. Pick the **LUT** by not choosing at all: on an FPGA, write the function, count its inputs, and let the mapper do the Shannon expansion it was built to do.
